# 100% line and branch coverage, enforced in CI

Backend (`pytest --cov-branch --cov-fail-under=100`) and frontend (Vitest v8, all thresholds 100) both fail CI below 100% line *and* branch coverage. Exclusions are limited to a short reviewed list: entrypoint `__main__` blocks, generated API client code, Alembic migrations, and the local Embedding Model's adapter (`app/embeddings/local.py`), which can't run without downloading its model and is covered by the live suite instead. Migrations are covered instead by an upgrade/downgrade round-trip test. Model calls and Docling are faked at a single seam each, using Pydantic AI's `TestModel`/`FunctionModel` and a fake converter. Tests against real providers run in a separate marked suite outside the gate. Don't add ad-hoc `pragma: no cover`; write the test or change the design.

**Amended by ticket 03-02.** The local Embedding Model adapter joined the exclusion list. It is a thin wrapper over fastembed and a Hugging Face tokenizer, and both download the model on first use, which the gate can't depend on. Everything around it (the embedder port, the hash-based fake, the chunker and the pipeline) stays inside the gate. Docling's adapter stays inside too: Markdown and DOCX convert with no models, so the gate runs real Docling on them.
