# Layered prompt-injection defence, with no side-effecting tools

Agents never get tools that change anything outside the conversation, so a successful injection can at worst produce a bad answer. On top of that limit we layer: spotlighting (Visitor input and retrieved Chunks wrapped as labelled, untrusted data), an input Guardrail classifier configurable per Agent (block, warn or log), a canary token whose appearance in output blocks the response, ingestion-time scanning that flags instruction-like Chunks, and an attack-prompt evaluation suite run in CI. Every block is logged against its Message with a reason.

The input Guardrail defaults to a platform-run local classifier (a small ONNX prompt-injection model, alongside the local embeddings). It needs no credentials, costs nothing per message and is deterministic in tests. An Agent can additionally enable an LLM classifier that uses its own Provider Credential.

The local classifier is Protect AI's `deberta-v3-base-prompt-injection-v2` (Apache-2.0, ONNX export, pinned to a Hugging Face revision), run with ONNX Runtime and bundled in the API image. Its `small` sibling is gated on Hugging Face, so the base model (about 740 MB) is used; it scores a message in about 0.1 s on one CPU core. Messages longer than its 512 tokens are scored in overlapping windows and the highest score counts, so an attack can't hide after a long preamble. In block mode a flagged message short-circuits the runtime: no retrieval, no model call, the Agent's refusal text, and a Guardrail outcome with the score and reason on the Message. A blocked turn is also left out of the history later turns send to the model.

The canary token is a fresh random value per request, placed in the platform preamble. A streaming filter holds back a buffer as long as the canary and releases text only once it cannot be the start of the canary, comparing without case or whitespace, so the canary is caught even when split across stream chunks and no fragment of it reaches the Visitor; the reply is then cut and replaced with the Agent's fallback text. **Limitation:** a canary the model disguises (characters separated by punctuation, reversed, base64-encoded) is only found by a post-completion check of the whole answer, which logs it and flags it as a Guardrail outcome on the Message, but cannot un-send what has already streamed. Other encodings (hex, translation, paraphrase) are not detected at all; the input Guardrail and the evaluation suite are the defences there.

The LLM classifier (ticket 08-03) runs only on messages the local classifier passed, so a message the free local check already blocks costs no provider call, and only in block mode: warn and log mode (08-02) act on the local classifier's flag alone for now, so neither pays for a provider call per message; extending the LLM classifier to them is a follow-up. It is a structured-output Pydantic AI call built by the model gateway from the Agent's own credential (no platform key), at temperature 0, with a fixed prompt that shows the message between `<message>` markers as untrusted data (any spelling of the closing marker inside it is escaped). A label of `injection` flags the message whatever its score. Provider errors, a reply that doesn't fit the schema after one retry, and no reply within `LLM_CLASSIFIER_TIMEOUT_S` (10 s by default) all count as the classifier failing; the Agent's fail mode (closed by default) then refuses the message or lets it through, and the Trace records an `unchecked` outcome either way. The classifier call's tokens are not yet added to the answer's tokens or Cost.

Warn and log modes (ticket 08-02) don't short-circuit. Warn answers the flagged message with a caution block added as the last system part of that turn's prompt (system text, so the model weighs it as an instruction rather than data, and placed after the Agent's own system prompt so it isn't overridden) and flags the answer Message (`action: flagged`). Log answers it exactly as an unflagged message and only records the verdict (`action: logged`), so Editors can measure false positives on real traffic before enforcing. Both keep the turn in later history: the model's own answer, not the attack, is what was replayed, and the caution applies to the flagged turn only.
