# The Studio has its own token-based design system with a light and dark Appearance

The Studio was styled page by page with Tailwind's slate palette, a side menu and tab rows. We adopt one design system, Tidepool (docs/design/README.md): every colour is a CSS custom property in `apps/studio/src/design/tokens.css`, exposed to Tailwind as utilities (`bg-surface`, `text-muted`), and pages use shared class recipes and a few components from `apps/studio/src/design`. Light and dark are two values of the same tokens, switched by `<html data-appearance>` or the system preference, so pages never use `dark:` and one class list serves both. Navigation moves into a breadcrumb in a single top bar: Organisation, Project, section and item are each a crumb, and a crumb with siblings is a switcher menu. This replaces the side menu and the Project and Settings tab rows, giving pages their full width.

The Studio's light/dark setting is an **Appearance**, a per-browser preference, deliberately separate from an Organisation's widget **Theme** and **Theme Mode**: the Studio's tokens never style the widget or its preview, and the widget's Theme never styles the Studio. Tokens are checked for WCAG AA contrast in both Appearances by a test that reads the stylesheet, so a palette change that breaks contrast fails CI. We chose CSS variables plus recipes over a component library because the existing pages already share Tailwind class constants; swapping those for recipes reskins a page without restructuring it.
