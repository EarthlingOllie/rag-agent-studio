# A contextual sidebar replaces the breadcrumb switchers as the Studio's navigation

[ADR-0013](0013-studio-design-system.md) moved all navigation into the top bar's breadcrumb, where each crumb with siblings is a switcher menu. In review ([docs/reviews/candidate-reskin](../reviews/candidate-reskin/README.md)) that proved hard to use. No destination is visible until you open a menu. A crumb is both "where you are" and a menu of somewhere else: the Organisation's sections sit under the crumb labelled "Projects", and a Project's sections sit under whichever section is open. Security and Profile appear in two menus. An Agent is six crumbs and five menus deep, under three stacked headings. On a phone the bar wraps into three rows and the fold hides the crumbs you need.

We replace it with a **contextual sidebar** on the left of every signed-in Organisation page. From the top: the Organisation switcher, then the Organisation's links (Projects, Cost for Owners, Settings); inside a Project, a divider, the Project switcher (open Projects and All Projects), then the Project's sections (Documents, Instructions, Agents, Conversations, Analytics, Settings). The current link has the soft accent fill that the current crumb had, and `aria-current="page"`. Below `md` the sidebar is a drawer opened from a menu button in the top bar: focus is trapped, Escape closes it, and the current link is focused on open.

The top bar keeps the brand, a **plain breadcrumb** of links with no menus (it says where you are; the sidebar is how you move), the page's own actions (Publish, History, the saved state), the Appearance toggle and the account menu. Profile, Security and Sign out live only in the account menu. On narrow screens the breadcrumb shows its last two crumbs.

An Agent's views (Playground, Versions, Embed & limits, Conversations) become a tab row under the Agent's header instead of a crumb menu, and the Agent switcher is a ▾ on the Agent's title. Agent pages drop the Project's page header, because the sidebar and breadcrumb already name the Project, so an Agent page has one h1.

This amends ADR-0013's navigation and design principle 3 ("Navigation lives in the top bar's breadcrumb"). The tokens, recipes, Appearance and ratchet decisions stand. We considered visible tab rows under each header (it keeps the full width, but an Agent page would need three rows, and the Organisation's sections would crowd the top bar's actions). We also considered keeping the breadcrumb and adding a command palette (the smallest change, but first-time Members still couldn't find anything). The sidebar costs about 240 px of width, which the 1160 px content column absorbs at desktop widths.

Built in tickets 12-08 to 12-11. Two details settled while building it. The breadcrumb starts at the Organisation's page the Member is under (`Projects`, `Settings / Members`, `Northwind Handbook / Agents / HR helper`), not at the Organisation, which the sidebar already names, and each crumb's `aria-current` follows the page the Member is on rather than the router's own marking, so only the last crumb is current. Organisation settings' areas (General, Credentials, Models, Theme, Members, Audit), which only the breadcrumb's Settings switcher offered, become a tab row under the settings header, like an Agent's views: the sidebar keeps one Settings link, and a page's own views are tabs.
