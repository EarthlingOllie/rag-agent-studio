## What was built

- **Seed task** (`infra/modules/ecs/seed.tf`): an ECS task definition `<name>-seed` on the backend image at the deployed tag, ARM64 Fargate, read-only root filesystem with a scratch `/tmp`, command `python -m app.seed` (the command behind `make seed`). It gets the API's settings minus the API-only ones (no `DEMO_PAGES`, `BEDROCK_PLATFORM_PRINCIPAL`, `TRUSTED_PROXIES`) and the API's secrets (database password, Redis token, session secret, local key, Logfire when given), because the seed runs the API in process. Its own task role has the API's documents-bucket and credentials-key statements and **not** the API's `sts:AssumeRole` for customer Bedrock roles; its own execution role pulls the image, writes only its own log group (`/ecs/<name>/seed`) and reads only its secrets. Its own security group has no ingress and egress only to HTTPS, Postgres and Redis. Size `seed_task_size`, default 1 vCPU / 4 GB, validated against Fargate's pairs. Outputs: `seed_task` (task definition, container, private subnets, security group, log group, stream prefix), `seed_security_group_id`, `seed_task_role_policy`, `seed_execution_role_policy`; `task_environment` includes `seed`.
- **Demo environment** (`infra/envs/demo`): the database and the cache admit the seed security group; the `deploy` output carries `seed_task`, so a deploy registers the seed task at the tag it deploys.
- **Seed script** (`scripts/deploy/seed.sh [--reset]`): `terraform init` against the state bucket and `terraform output -json deploy` (never apply); `aws ecs run-task` of the seed task in the private subnets without a public IP (`--reset`: a container command override `python -m app.seed --reset`); `aws ecs wait tasks-stopped` up to `SEED_WAIT_ROUNDS` times (default 6, about an hour); the `seed` container's exit code; then the task's CloudWatch log (stream `seed/seed/<task ID>`) printed and added to the job summary, so the demo sign-in details and URL show in the run. A not-deployed environment, one deployed before the seed task existed, a task that cannot start, never stops, or exits non-zero each fail the run with the reason; bad arguments or missing `TF_STATE_BUCKET` / `AWS_REGION` stop before any call.
- **Workflow** (`.github/workflows/seed.yml`): `workflow_dispatch` with a boolean `reset` input; `environment: demo`; the `demo-environment` concurrency group shared with deploy and destroy (no cancelling); GitHub OIDC role `AWS_DEPLOY_ROLE_ARN` and `TF_STATE_BUCKET` checked first; installs Terraform and runs `seed.sh` (with `--reset` when ticked).
- **Image** (`backend/Dockerfile`): `COPY --from=seed documents /seed/documents`, the folder `python -m app.seed` reads by default (`DEFAULT_ASSETS`), so the task needs no mount. Every build passes the repository's `seed` folder as the `seed` build context: `make images` (`--build-context seed=seed`) and `docker-compose.yml` (`additional_contexts`). `make seed` still mounts the same folder over it.
- **Docs**: a root `README.md` (run locally; deploy, **seed** and destroy the AWS demo), a "Seed (fill the demo with data)" section in `docs/deploy-demo.md` (steps, what the script does, permissions, cost, laptop use) and its tables updated; `GLOSSARY.md` (**Demo Organisation**: the seed workflow builds it in AWS); ADR-0012 gains the AWS paragraph and two considered options.
- `make infra-check` runs the new `scripts/deploy/tests/seed.test.sh`.

## Gaps (only a real AWS account can show these)

- **Nothing ran against AWS.** No `terraform apply`, no ECS task, no OIDC exchange: the run-task, waiter, describe-tasks and get-log-events calls are asserted against stubs, and the infrastructure with the mock provider. Unverified: that Fargate starts the seed task with these roles and secrets; that the seed's presigned PUTs to the SSE-KMS documents bucket succeed from the private subnets through the S3 endpoint/NAT; that the worker service ingests the seeded Documents in time (the seed waits for Ready); the CloudWatch stream name `seed/seed/<task ID>` (the documented awslogs format); and the seed's real duration on 1 vCPU / 4 GB (best guess: a few minutes; `SEED_WAIT_ROUNDS` allows about an hour and the job `timeout-minutes: 75`).
- **No workflow ran on GitHub** (Actions is down). `seed.yml` passed actionlint with shellcheck; the `workflow_dispatch` boolean input, the `demo` environment and the shared concurrency group are unverified there.
- **The deploy role's permissions** for `ecs:RunTask`, `iam:PassRole` on the seed roles and `logs:GetLogEvents` are assumed from the bootstrap's PowerUserAccess plus `iam:PassRole` on `studio-*` roles (`infra/bootstrap/main.tf`); not exercised.
- **Real Provider Credential in AWS:** not supported by the seed workflow by design (a key in run-task overrides would be visible in the task description); the AWS demo seeds the Demo model and a real credential is added in the Studio (ADR-0012).
- **A first seed that fails part-way** (as above) needs the workflow's `reset`; a plain re-run stops with that instruction rather than repairing it.
- **Image size:** the demo Documents add about 72 KB to the backend image. The production arm64 build with PDF support was not built here (disk); the sandbox build is `WITH_PDF=false`, models bundled.
