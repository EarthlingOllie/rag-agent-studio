## What was built

- **Seed** (`backend/app/seed/content.py`, `runner.py`): the seed now also publishes, through the API, the two Agents the demo pages embed, if they are not Live yet: the **Product FAQ** (the shop pages' Agent) and a new **Low-budget helper** (Products Tag, daily Token Budget 2,000, its own Unavailable text "Northwind's low-budget helper has used today's budget. Please come back tomorrow."). Each gets the shop origin as its only Allowed Origin through the Operational Settings endpoint, and the seed puts those settings back on every run (idempotent). The shop origin is `DEMO_SHOP_ORIGIN` (compose: `http://localhost:5175`), else the Studio's own origin (`STUDIO_URL`), which is what the AWS demo uses, as the pages are under `/demo/` there. The HR helper stays a Draft (10-02 builds its Version history). The seed prints `Demo pages: <origin>/demo/`. The Theme's light accent moved from `#b45309` to `#9a4508`: the old one was 4.2:1 on the widget's answer bubble (axe failed the citations on the shop page), the new one 5.5:1.
- **API** (`backend/app/seed/demo_pages.py`, in `app.main.ROUTERS`; settings `DEMO_PAGES`, `DEMO_SHOP_ORIGIN` in `app/core/settings.py`): with `DEMO_PAGES=true` only (else 404),
  - `GET /api/demo/agents` → `{widget_url, shop: {public_id, name}, budget: {public_id, name, daily_token_budget}}` for the Demo Organisation's live, unarchived Product FAQ and Low-budget helper (found as the seed finds the Organisation: through the demo Owner); 404 "The demo isn't seeded yet. Run `make seed`." before seeding;
  - `POST /api/demo/agents/{public_id}/exhaust-budget` → adds what is left of today's budget to the Agent's Redis counter (`Admission.record_usage`, as Visitor replies do) and raises its Budget alert through `embed.service.budget_exhausted` (one Owner email per day, as for a real exhaustion); returns `{tokens_used, daily_token_budget}`. Only the Low-budget helper; any other public ID is 404. A second click changes nothing.
  - Both are anonymous, like the widget API, and left out of the OpenAPI document (no Studio code calls them, so the generated client is unchanged).
- **Pages** (`frontend/apps/widget/host/`): static HTML, no build. `demo/index.html` (Northwind's fictional shop, the Product FAQ as a bubble), `demo/inline.html` (a help-centre page, the same Agent inline in `#chat`), `demo/budget.html` (the Low-budget helper inline, and a **Use up today's Token Budget** button with a status line). Each asks `/api/demo/agents` which Agent to embed and pastes its Embed Snippet (`<widget_url>/embed.js`, `data-agent`, `data-launcher`, `data-target`). `blocked.html` pastes the Product FAQ's snippet from an origin no Agent allows and explains, in a red dashed box, that the browser refuses to show the chat.
- **Local serving** (`serve.mjs`, the compose `host` service): port 5175 (the shop origin) serves `/demo/…` (and still `/?agent=…` for other specs); port 5176 (`BLOCKED_PORT`) serves `blocked.html` at `/`; both proxy `/api/demo/` to the API (`API_URL`), as CloudFront sends `/api/*` to the API in AWS. `docker-compose.yml` sets `DEMO_PAGES=true` and `DEMO_SHOP_ORIGIN` for the backend and publishes 5176.
- **AWS** (the demo path): `scripts/deploy/deploy.sh` uploads `frontend/apps/widget/host/demo` to the static bucket under `demo/` (HTML no-cache) and invalidates `/demo/*`; the disallowed-origin page is not uploaded (local-only, as the spec says). The CloudFront SPA-fallback function serves `/demo/` as `/demo/index.html` (not the Studio's) and redirects `/demo` to `/demo/`. The ecs module gains `demo_pages` (default false), which sets `DEMO_PAGES=true` on the API container only; `infra/envs/demo` turns it on.
- **Docs**: `GLOSSARY.md` (new **Demo pages**; **Demo Organisation** updated), `docs/development.md` (URLs and routes).

## Gaps and best guesses

- **Best guesses, recorded instead of asking:**
  - **A third Agent** for the budget demo (the Low-budget helper), so exhausting it never takes the shop's Product FAQ offline; spec 10 speaks of two Agents for the seeded history, which 10-02 builds on the HR helper and Product FAQ. 10-02 should keep the Product FAQ's Live Version and Allowed Origins (this seed publishes v1 only when it is not Live).
  - **Budget of 2,000 tokens a day**: a few demo answers before it runs out naturally; the button spends the rest at once.
  - **The button spends the counter directly** (as real usage would) rather than sending messages until it runs out: one click, deterministic, and the same alert and email path as a real exhaustion. It is an anonymous route, so anyone who can open the demo can spend the demo Agent's budget for the day; it exists only with `DEMO_PAGES` on and only for that Agent.
  - **How the pages find the Agents**: a demo-only API route rather than public IDs baked into the pages, so the same static files work locally and in AWS, before and after `make seed-reset` (new public IDs).
  - **Visibly fails**: the browser's own refusal (its error frame) inside a red dashed "Blocked" box with an explanation; a cross-origin page cannot detect the refusal itself.
  - **Seed Theme accent** darkened for WCAG AA in the widget (a 10-01 value).
- **Sandbox limits** (as in earlier tickets): images built with `WITH_PDF=false BUNDLE_MODELS=true` ([build.sh](build.sh) adds only the egress proxy CA); the e2e stack runs `EMBEDDER=fake` and the fake model gateway, and the demo model answers (no real provider or key); host ports are moved by [compose.sandbox.yml](compose.sandbox.yml) and [e2e.env](e2e.env) (shop `27475`, disallowed `27476`). The e2e run covers this ticket's spec and its neighbours that use the host page, not the whole suite. Nothing was deployed to AWS: the `/demo/` path is evidenced by the deploy script's tests, the CloudFront function's tests and `terraform test`. `registry.terraform.io` is blocked here, so `make infra-check` used a scratch filesystem mirror of `hashicorp/aws` (as earlier tickets did). The live suite and the Trivy scan were not run.
