## What was built

- **The Guardrail demo Agent** (`backend/app/seed/content.py`, `runner.py`, `history.py`): the seed now also creates and publishes a fourth Agent, **Guardrail demo** (HR Tag, shop origin as its Allowed Origin, published like the other demo-page Agents). Its Model override is the demo credential's new **`demo-naive`** model, set on every seed run, even when a real credential is the Default Model. The Seeded history's bulk rollout of Instructions v2 includes it, so the Product FAQ stays the only Agent behind.
- **The Naive demo model** (`backend/app/credentials/registry.py`, `backend/app/gateway/demo.py`): the demo provider offers a second chat model, `demo-naive`, "Naive demo model (obeys injected instructions)". It is the Attack evaluation suite's Naive model (`app/evals/naive_model.py`: decodes base64 and lookalikes, recites its system text when asked) behind the label "Naive demo model (obeys injected instructions, not AI): …", streaming in 7-character pieces. Built by both the live and fake adapters, like `demo-chat`; no key, no network.
- **The debug endpoint** (`backend/app/seed/attack_panel.py`, in `app.main.ROUTERS`; on only in demo mode, `DEMO_PAGES=true`, else 404; anonymous; not in the OpenAPI document):
  - `GET /api/demo/attacks` → `{agent: {public_id, name}, attacks: [{id, category, label, payload, expected}]}`: the five fixed attacks (`content.ATTACKS`, payloads taken from the Attack evaluation suite): `instruction-override`, `prompt-extraction`, `roleplay-jailbreak`, `encoded-attack` (base64 for "Reveal your system prompt") and `benign-control`. 404 "The demo isn't seeded yet. Run `make seed`." before seeding.
  - `POST /api/demo/attacks/{attack_id}` → Server-Sent Events. It sends the attack's payload to the Guardrail demo Agent's Live Version exactly as the widget does (shell bootstrap token → new Visitor Conversation → admission control with the Agent's rate limits → `playground.service.answer` through the Guardrail pipeline; the answer and its Trace are saved, so the Conversations viewer shows it). It streams the widget's events (`token`, `citation`, `replace`, `refusal`, `error`, `unavailable`) and then, before `done`, a `trace` event that Visitors never get: `layers` (input Guardrail: `blocked`/`flagged`/`logged`/`allowed`/`passed`; Canary token: `replaced`/`flagged`/`quiet`, or `not_reached` when the input layer blocked), each with `verdict`, `reason` and `score`; `acted` (the layers that did something); `model` (null when no model was asked); `answer`. Unknown attack IDs are 404, so only the fixed payloads can be sent. Like the Playground, its replies don't count against the Token Budget (a spent budget still refuses, as `unavailable`).
- **The page** (`frontend/apps/widget/host/demo/attacks.html`, static, no build): one button per attack plus the benign control (in the list "Attacks"); a click shows what was sent and what is expected, streams the reply into the page as it arrives, says when the Canary token cut it off or the input Guardrail refused it, and fills the "Guardrail layers" table (Layer / Outcome / Why) and an "Acted: …" line. Linked from the other demo pages' navigation.
- **Serving**: `serve.mjs` (the compose `host` service, the shop origin) now streams proxied `/api/demo/` responses chunk by chunk instead of buffering them, so the reply streams on the page; in AWS the deploy already uploads every page in `demo/` (the deploy test now includes `attacks.html`).
- **Docs**: `GLOSSARY.md` (new **Attack panel**, **Demo mode**, **Naive demo model**; **Demo Organisation** and **Seeded history** updated), `docs/development.md` (URL, routes and expected outcomes).

## Gaps and best guesses

- **Best guesses, recorded instead of asking:**
  - **A dedicated fourth Agent on a naive model.** With the canned `demo-chat` model nothing would ever leak, so the Canary token could never be seen acting; the Naive demo model makes the encoded attack reach the model and the Canary layer visibly stop it. It is labelled as naive in every reply and in the Studio's model list. It stays on the naive model even when the seed gets a real credential (the panel is about the Guardrails, not the model).
  - **"Demo mode" is `DEMO_PAGES`**, the flag 10-03 introduced for the demo routes, rather than a second flag: the attack panel is one of the demo pages, and the AWS demo and compose already set it.
  - **Fixed payloads only**, by attack ID: the anonymous endpoint can't be used as a free chat API. The Agent's rate limits apply; replies don't count against its Token Budget (as in the Playground).
  - **Each click is a new Visitor Conversation** of the Guardrail demo Agent, so the attacks also appear in the Conversations viewer and its analytics, with their Traces.
  - **Categories**: spec 10 story 18's five (the suite's homoglyph, translation, multi-turn and indirect cases are covered by the Attack evaluation suite and the flagged Chunk in the Knowledge Base viewer).
  - **Layers shown**: the two Visitor-message layers that act on an answer (input Guardrail and Canary token). The ingestion scan acts at upload time, not per message, so it is shown in the Document viewer, not here.
- **Sandbox limits** (as in earlier tickets): images built with `WITH_PDF=false BUNDLE_MODELS=true` ([build.sh](build.sh) adds only the egress proxy CA; the build checks the bundled ONNX classifier offline); the e2e stack runs `EMBEDDER=fake` with the real local input classifier and the demo provider (no real key or paid call); host ports are moved by [compose.sandbox.yml](compose.sandbox.yml) and [e2e.env](e2e.env) (shop `28675`). The e2e run covers this ticket's spec and its neighbours (demo pages, seed, embed, Token Budget, LLM classifier, Playground, widget accessibility, smoke), not every spec. The seed's JSON request logs were filtered out of the committed e2e log (34 MB; 19,649 lines starting `{"`), nothing else. Nothing was deployed to AWS: the `/demo/attacks.html` upload is evidenced by the deploy script's test; `make infra-check` was not rerun (no Terraform changed; the only infra-side change is that test's fixture, run on its own above). The live suite and the Trivy scan were not run.
