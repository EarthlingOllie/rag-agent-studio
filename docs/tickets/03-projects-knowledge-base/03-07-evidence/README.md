## Decisions and notes (best guesses recorded instead of asking)

- **A flag blocks nothing.** A flagged Chunk is stored, embedded and retrievable like any other; the spec asks only to flag and show. Spec 04's spotlighting and spec 08's guardrails are the defences at answer time. Blocking or excluding flagged Chunks from retrieval would be a later product decision.
- **Only flagged Chunks keep a verdict.** Unflagged Chunks have all three columns null rather than a "benign" label and a low score; the heuristic has no meaningful score for text that matches nothing. Spec 08's ONNX classifier can start storing scores for every Chunk without changing the API (`flag` stays null below its threshold).
- **Every match flags.** Each pattern's score is at least 0.6, so the heuristic has no separate threshold; the combined score ranks how many signals agree.
- **The heuristic is deliberately simple** (spec 03's risks): English phrases only, patterns rather than a model. Paraphrased or non-English injections get past it; spec 08 hardens it behind the same port, and its eval suite (08-07) measures that.
- **The scan runs after embedding** (spec 03's pipeline order, step 6) and in the same failure path: a classifier error fails the Document with the generic message. Ticket 03-04 (in progress in parallel) categorises failures; a classifier error would fall in its default category.
- **Counts follow `chunk_count`'s rule** (the current edition's Chunks), so during a re-embed (03-10, not built yet) both stay consistent with each other.
- **The Flagged column is its own column** after Chunks, so existing tests that read the Chunks cell by position still do.
- **Migration number.** `0019_chunk_guardrail_flags` follows `0018_document_failures` (03-04), the head on candidate at `7e2f530`; it was `0016`, then `0018`, before the merges.
- **Failure category of a scan error (best guess, no one to ask).** 03-04 defines no category for the Guardrail scan, so a classifier crash falls into its catch-all `conversion` category. A dedicated category would need a 03-04 enum change; left as is.
