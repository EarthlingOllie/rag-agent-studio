## Decisions and notes (best guesses recorded instead of asking)

- **"Before upload".** The Studio validates type and size in the browser before any request. The API also enforces every check at presign and at confirm, because a presigned PUT can't bound the size.
- **Content checks.** Content checks are cheap and need no Docling: a `%PDF-` header, an Office zip containing its main part, and UTF-8 without NUL for the text types. A mismatch is "unsupported content", not "conversion".
- **Which failures are transient.** Only provider failures (`EmbeddingProviderError`) are retried automatically. Since 03-09, `ProviderEmbedder` maps any error from the gateway's client to it. Setup problems are not transient and fail at once with the provider category: a missing credential, a model the credential doesn't offer, an unsupported credential kind (`UNUSABLE_ERRORS`, now shared by the retrieval probe and ingestion) and wrong-size vectors. 03-09's earlier generic message ("This Document couldn't be processed…") for a provider failure is replaced by the provider category's message, and its test was updated.
- **Who may retry.** Any Member (Owner or Editor). Only Owners change the quota. The spec's "quota display" in Project settings is the quota line on the Documents tab. The Studio has no control for changing the quota yet: Owners use the API.
- **One retry route with 03-08.** Both tickets added `POST …/retry`. The merged rule is "retry what failed; with nothing Failed, reprocess the Ready Document". So for a Ready Document beside a Failed new edition, Retry now retries that edition, not the current one. 03-08's test of the other behaviour was rewritten to match (`test_retry_beside_a_failed_replacement_retries_the_replacement`). To reprocess the current edition with OCR in that case, upload the edition again. The status is 03-08's 202.
- **No readable text vs 03-08.** 03-08 left a scanned PDF without OCR as Ready with 0 Chunks. This ticket's categories make it Failed (unsupported content), with "No readable text was found in this file. Check that it isn't empty. If it is a scanned PDF, turn on OCR for this Project, then retry it.". A reprocessed Document that fails drops its old Chunks, so a Failed Document never has Chunks. 03-08's tests were updated to match, and their fake PDFs now start with a `%PDF-` header line, which the fake converter skips.
- **What the quota counts.** Documents that aren't Failed. Lowering the quota keeps the Documents already there.
