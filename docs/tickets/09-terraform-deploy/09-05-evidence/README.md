## Decisions recorded (best guesses, no human asked)

- **Own cache, origin request and response headers policies, not AWS-managed IDs.** The dynamic cache policy matches the managed CachingDisabled policy, and the origin request policy matches AllViewerExceptHostHeader. Defining them here means the tests can assert their contents, not just an opaque ID.
- **SPA fallback in a CloudFront Function, not a custom error response.** Custom error responses apply to the whole distribution, so they would mask API 403 and 404 responses (the ALB's 403 without the secret header, for example) behind the Studio's HTML. The rule is "no file extension in the last segment". So a route whose last segment contains a dot (for example `/docs/v1.2`) is not rewritten. Studio routes use IDs, so none are expected.
- **The certificate is placed in us-east-1 with AWS provider 6.x's resource `region` argument,** not a second aliased provider. The module and environment stay single-provider, and the tests can assert the region directly.
- **Read timeout of 60 s by default.** That is CloudFront's maximum without a quota request. The timeout applies between response packets, not to the whole stream. So SSE works as long as the API sends a heartbeat at least every 60 s. Values up to 180 s are accepted for when a quota increase is granted.
- **Compression is off on dynamic paths** so streamed chunks are not held back. Static paths compress with gzip and brotli.
- **`https-only` on dynamic paths** (HTTP is refused, not redirected), because a redirect would turn POSTs into GETs. Static paths redirect.
- **Security headers.** The Studio and widget assets get HSTS (1 year, includeSubDomains), nosniff, `strict-origin-when-cross-origin` and `X-Frame-Options: DENY`. The API gets HSTS and nosniff only. The widget shell is framed by customer sites under the per-Agent CSP, so CloudFront must not add frame or CSP headers to it.
- **Checkov skips, each justified inline:** WAF and its Log4j rule (out of scope in spec 09), access logging (cost), geo restriction (the demo is public), origin failover (one region), TLSv1 minimum with the default certificate (CloudFront fixes it, per ADR-0011; custom domains get TLS 1.2, which is asserted), and HSTS preload (`*.cloudfront.net` is not ours to preload). Without the CKV_AWS_174, CKV_AWS_259 and CKV_AWS_68 skips, Checkov fails ([gate-demo.log](gate-demo.log)).
- **Outputs for ticket 09-06.** The environment now outputs `cloudfront_url` (to print and smoke-check), `cloudfront_distribution_id` (for invalidations) and `static_bucket_name` (for the upload).

## Needs a real AWS account (not verified here)

- `terraform plan` and `apply` against AWS. Nothing was applied, and no cloud resources were created. These points are unverified:
  - Whether CloudFront creates the distribution with this origin request policy (`allExcept` with `host`) alongside the ALB custom header.
  - Whether the ALB listener rule matches the `X-Origin-Verify` header CloudFront sends. This is the end-to-end check of ADR-0011, carried over from 09-04.
  - Whether SSE streams through the edge without buffering, and whether the API's heartbeat keeps each gap under the 60 s read timeout.
  - Whether the `Authorization` header reaches the ALB. CloudFront forwards it only on some methods unless it is part of the cache policy. The API uses session cookies today, so this only matters if bearer tokens are added later.
  - Whether the API sees the right scheme and host behind CloudFront. Host is the ALB's name, and the API may need `CloudFront-Forwarded-Proto` or an explicit public origin setting. That is app work for ticket 09-06.
  - Whether the SPA function runs on the real `cloudfront-js-2.0` runtime. It is tested in Node with the same code, which uses only ES5 string methods.
- ACM DNS validation and Route 53 records for a real domain and hosted zone. None exists for the demo.
- The OAC read path end to end: S3 bucket policy `AWS:SourceArn` matching the real distribution ARN.
