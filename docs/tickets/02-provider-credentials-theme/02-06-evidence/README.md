## Decisions and notes (best guesses recorded instead of asking)

- **Images apply on upload**, not with "Save Theme": an upload is already a deliberate step, and holding it in the draft would leave orphan files for unsaved drafts. The Studio says so ("Images apply as soon as they are uploaded").
- **Types: PNG, JPEG, WebP only; 1 MB limit** (`MAX_THEME_IMAGE_BYTES`). SVG is refused because it can carry script and the image is served from the API's origin.
- **Double check on confirm.** The extension and declared size are checked before presigning, and the stored bytes are checked again (size and magic bytes) on confirm, since the presigned PUT can't enforce either.
- **Storage:** nullable JSONB columns `themes.logo` / `themes.avatar` (key, type, size, SHA-256, time). Images are served through the API (`Cache-Control: private, immutable`, URL changes per upload) rather than presigned GETs, so the widget can later use the same stable URL.
- **Audit:** image changes use the existing `theme.updated` action with only the changed image in `before`/`after`, rather than a new action.
