## Decisions and notes (best guesses recorded instead of asking)

- **Units.** US dollars per million tokens, stored as `NUMERIC(12, 6)` and returned as decimal strings, so no amount passes through a float. The Studio shows them with 2 to 6 decimals ("$0.075").
- **Three prices.** `input` is uncached input, `cached_input` is cache reads. Cache writes (Anthropic) are not priced separately; `TokenUsage` has no field for them yet. Embedding and rerank models have `output` 0 and `cached_input` equal to `input`.
- **Overrides are per credential and model**, since one credential offers several models at different prices. A partial override is allowed; a missing price stays the platform's.
- **Overrides are not dated.** They apply from when they are saved. The plan freezes each Message's cost when it is written (spec 07), so a later override doesn't rewrite past costs; the platform table is dated because the repo can record a price change ahead of time and the cost function must pick the right one.
- **Loaded on every migrate, not in a data migration.** A data migration would load the file once; reloading after every `upgrade` keeps the table equal to the repo without a migration per price change.
- **Unknown cost is `None`, not 0**, so cost reporting can tell "free" from "no price".
- **Prices in the file** are the providers' published list prices as best known on 2026-11-05, with each model's release date as `effective_from`; they are data to be checked and updated, not fetched (automatic price updates are out of scope).
- **Every Member reads prices** (like the Default Model and model lists); only Owners override them.
- **The PUT body names the model** rather than the path, because Bedrock model IDs contain `:` and `.`.
