**Seams under test.** These come from spec 02's testing decisions and the shared test seams. There was no one to confirm them with, so this is the recorded choice.
- **API seam** (primary): the in-process `httpx` client against real Postgres and Redis, observing everything (model lists, the Default Model, Audit Events, delete refusals) through the API.
- **Model gateway seam**: `ModelGateway`'s three factory methods. This is the "Chat model" and "Embedder" port of the shared seams table, so it is where the fakes plug in. Its live adapters are tested with an `httpx2.MockTransport` that answers with recorded Anthropic (SSE), OpenAI and Voyage response shapes; no provider is ever called.
- **Network seam**: Studio tests with Testing Library and MSW, handlers typed by the generated client.
- **End-to-end seam**: Playwright and axe against the compose stack, with the fake verifier and the fake gateway adapters.

## Decisions and notes (best guesses recorded instead of asking)

- **Pydantic AI 2.66** (`pydantic-ai-slim[anthropic,openai]`) is the new dependency. Its provider clients take `httpx2` clients, so the gateway shares one `httpx2.AsyncClient`; the credential verifier keeps its `httpx` client.
- **Embedders are Pydantic AI `EmbeddingModel`s.** OpenAI uses Pydantic AI's own; Voyage is a small `EmbeddingModel` subclass over HTTP, because Pydantic AI's Voyage model needs the `voyageai` SDK.
- **Rerankers are this project's own `Reranker` port**, since Pydantic AI has none. Voyage `rerank` is the live adapter.
- **Bedrock.** Bedrock credentials can't be created until 02-02, which also defines their secret format. The live adapters refuse Bedrock with `UnsupportedCredentialError`, tested for all three capabilities; 02-02 adds the Bedrock clients in `LiveModelAdapters`. The fake adapters build Bedrock models like any other.
- **The model list route** takes the capability as a path segment (`…/models/{capability}`), so it fits the parametrised isolation suite like every other route.
- **A credential whose last check failed** can still be chosen: the check is advisory, as in 02-01, and the Owner sees its status on the Credentials tab.
- **No "clear the Default Model" action.** The ticket asks only to set it; clearing can come with spec 04 if Agents need it.
- **The fake chat reply names provider and model,** so later e2e tests can see which model answered.
- **The fake embedder** gives 16-dimension unit vectors from SHA-256; spec 03 can widen it when pgvector columns fix a dimension.
- **The price table** belongs to 02-04, which adds it to the Models tab.

## Gaps and sandbox notes

- **No real provider keys exist.** The live adapters are proven only against recorded response shapes through `httpx2.MockTransport`; no `@pytest.mark.live` test against real providers is included.
- **Bedrock models** are not built by the live adapters yet (see above; ticket 02-02).
- **One flaky Studio test.** The first fresh-clone `make test-frontend` (at `ed6a69a`, while the backend suite and mutation proof ran beside it) had one timeout, in the unrelated `ProjectPage.test.tsx` ([frontend-tests-first-run.log](frontend-tests-first-run.log)). The run in `frontend-tests.log` passed.
- **Images and stack.** Images were built from the committed Dockerfiles with only the sandbox proxy CA and proxy environment added to the first stage ([build.sh](build.sh)). The stack ran as compose project `rag0203` with [compose.sandbox.yml](compose.sandbox.yml) moving host ports (Studio `51173`, API `51800`, Mailpit `51825`) and `STUDIO_URL=http://localhost:51173`. Chrome came from `/usr/bin/google-chrome`. Trivy (`make image-scan`) was not run: the disk had about 2.5 GB free.
- **Migration numbering.** This ticket adds `0008_default_models` after `0007_provider_credentials`. A ticket built in parallel that also adds an `0008` (02-02, 03-02…) must re-parent whichever merges second.
- **Shared files.** `app/main.py`, `tests/integration/test_tenant_isolation.py`, `test_openapi.py`, the generated API client, `OrganisationSettings.tsx` and `router.tsx` are edited by most tickets; expect simple merge conflicts there.
