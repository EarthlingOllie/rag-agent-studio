## What was built

- **`time_series` query** (`backend/app/analytics/service.py`), beside 07-04's `version_metrics` in the analytics module: `time_series(agent, metric, granularity, start, end, today)`.
  - **Metrics** (`TimeSeriesMetric`): `conversations`, `replies`, `cost_usd` (total frozen cost), `mean_tokens`, `thumbs_up_rate`, `mean_rating`, `fallback_rate`, `p95_latency_ms`. Each point carries its value (null when there is no sample, e.g. no votes for a rate: a gap, not zero) and its sample size `n`.
  - **Granularity** (`TimeSeriesGranularity`): `day`, `week` (ISO weeks, Monday to Sunday) or `month`; the first and last periods are clipped to the range.
  - **Data**: every Version of the Agent together; days before today from the `usage_daily` rollups (07-04), today (the live partial day) from the raw tables through 07-04's `usage_on`; only Visitor Conversations (the Playground never counts). Weeks and months merge the daily counts and histograms, so a period's p95 is the merged histogram's.
  - **Live History markers**: every `agent_live_history` entry whose time falls in the range, in Live History order: when, the UTC day, the start of the point that day is in, the action, and the Versions from and to.
  - **Document changes** (the confounder): in the Agent's Project during the range, Documents added, replaced or processed again (`created_at` or `updated_at` in the range, each Document counted once) and Documents deleted (`document.deleted` Audit Events of the Project in the range).
- **API** (`backend/app/analytics/api.py`): `GET /api/organisations/{org}/projects/{project}/agents/{agent}/time-series` (`getTimeSeries`, Editors and Owners): `metric` (required), `granularity` (default `day`), `start`/`end` UTC dates with the same defaults and limits as `getVersionMetrics` (last 30 days to today, at most 366 days, start after end → 422; now one shared `_range`). Response: `metric`, `granularity`, `start`, `end`, `points [{start, end, value, n}]`, `markers [{occurred_at, day, point_start, action, from_version, to_version}]`, `document_changes {changed, deleted}`.
- **Studio** (`frontend/apps/studio/src/projects/TimeSeriesChart.tsx`, `useTimeSeries` in `analytics.ts`; one line in `AnalyticsTab.tsx`): an **"Over time"** section under the KPI cards, with **Metric** and **Granularity** pickers; the range is the tab's From/To (UTC) pickers, shared with the KPI cards. A **Recharts** `LineChart` of the metric (gaps where there is no sample) with a dashed **`ReferenceLine` per point holding Live History entries**, labelled with each Version made Live ("v2", or "v1, v2, v1" when several changes share a point); the changes listed in words ("2026-11-06: v2 published (from v1)", "v1 reverted to (from v2)", "bulk published", "bulk reverted to"); a table of the numbers behind the chart (period, value in the metric's units, n with what it counts); and the **confounder note** (`role="note"`): "Documents changed during this period: 2 added, replaced or processed again, 1 deleted. The Knowledge Base isn't versioned, so these changes may confound the comparison: a difference across a marker may come from the Documents rather than the Version."
- `recharts` 2.15.4 added to the Studio (the plan names Recharts for the Studio's charts). Generated API client regenerated. **Glossary**: **Time series**, **Live History marker**, **Confounder note**.

## Gaps and judgement calls

- **Seams not confirmed with a human.** The TDD skill asks for seams to be agreed first; no human is reachable, so the spec's own seams were used.
- **What "Documents changed" counts.** There is no Document change log, and adding one would need a migration while five sibling tickets add migrations. Best guess without one: Documents of the Project whose `created_at` or `updated_at` falls in the range (added, replaced, or processed again: a retry or reprocess also touches `updated_at`, and it does change what retrieval finds), each counted once, plus the Project's `document.deleted` Audit Events in the range. Uploads and replacements aren't audited, so a Document added and then deleted in the range counts only as deleted. The count is Project-wide, not narrowed to an Agent's Tag scope (04-04).
- **Document timestamps come from the database clock**, not the app's Clock (only the deletion's Audit Event uses the app Clock), so the API tests choose their ranges from the Documents list's own `created_at`/`updated_at` rather than the controllable clock.
- **Agent-wide numbers add up per Version.** A series covers every Version together, adding each Version's daily counts; a Conversation that two Versions replied in (the Live Version changed mid-Conversation) counts once for each, as in 07-04's per-Version KPIs.
- **Cost** in the series is the period's total frozen cost (sample size: Conversations); the KPI cards show cost per Conversation.
- **Markers by point:** markers sharing a point (several changes on one day, or in one week or month) are drawn as one dashed line labelled with each Version made Live in order; the list under the chart names every change with its day.
- **Chart size:** the chart is a fixed 720×280 SVG in a horizontally scrolling box (no `ResponsiveContainer`, which measures layout jsdom can't); the table below carries the same numbers for screen readers and narrow screens.
- **Default metric** is Conversations, by day, over the tab's range (the last 30 days unless From/To are set).
- **E2E flake outside this ticket:** 05-05's `bulk-rollout.spec.ts` timed out under load in the first e2e run and passed in the final one (see First runs).
