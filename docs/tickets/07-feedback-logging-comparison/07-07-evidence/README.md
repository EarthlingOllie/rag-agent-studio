## What was built

- **Migration `0038_retention_tombstones`** (after 07-04's `0037_usage_daily`):
  - `organisations.retention_days` (integer, default 90): the Retention Window.
  - `messages.purged_at`, with a partial index on `created_at` where `purged_at IS NULL` for the purge.
  - `conversations.deleted_at`: when an Owner deleted the Conversation on request.
  - `message_retrievals.document_name` (the tombstone: the Document's name when the answer was given), backfilled from `documents`; `chunk_id` and `document_id` become nullable and `document_id` is indexed. Retrievals of Documents deleted before this migration have no name to keep: their IDs are cleared and the name stays null. The downgrade drops tombstone rows (they have no IDs to go back to).
- **Retention module** (`backend/app/retention/`):
  - `service.py`:
    - `purge_messages(session, *conditions, now)`, the one purge path: clears the matching Messages' `content`, the `reason` in each of their Guardrail outcomes (a classifier's reason can quote or paraphrase the message; layer, verdict, action and score stay) and their Message Feedback `comment`, sets `purged_at`; every number and attribution (tokens, cost, latency, Agent Version, thumbs, ratings, retrievals) stays. A purged Message is never purged again.
    - `purge_expired(sessionmaker, at)`: for each Organisation, purges the Messages older than its Retention Window as of `at`, with no filter on Agent or Project state, so archived Agents and Projects are purged too. **Rollups first:** a Visitor reply on a day whose `usage_daily` rollup isn't final yet waits for a later run (it reuses 07-04's `pending_days`, renamed from `_pending`: the first day per Organisation, up to the cutoff, that isn't final). Playground Messages never go into the rollups, so they don't wait.
    - `set_retention_window(...)`: sets the window and records `organisation.retention_window_changed` (`before`/`after` `retention_days`); the same value again changes and records nothing.
    - `delete_conversation(...)`: through `purge_messages`, purges the Conversation's Messages at once, sets `deleted_at`, clears its Conversation token (the Visitor's widget can no longer resume or send) and records `conversation.deleted` (`before`: Project, Agent, Playground flag; `after`: Messages purged). Deleting it again changes and records nothing. The Conversation row stays, so its numbers stay in the metrics.
  - `tasks.py`: the Beat task `retention.purge_expired`, scheduled daily at 00:35 UTC (`app/worker/celery_app.py`), half an hour after the 00:05 rollup run finalises the previous day; `at=` (ISO time) redoes a run as of a time.
  - `api.py`: `PUT /api/organisations/{org}/retention-window` (`setRetentionWindow`, Owners only, 7 to 3650 days, else 422). `GET /api/organisations/{org}` (`getOrganisation`) now returns `retention_days`.
- **Conversations API:** `DELETE /api/organisations/{org}/projects/{project}/conversations/{id}` (`deleteConversation`, Owners only, 204; 404 outside the Project). The list and detail return `deleted_at`; each Message in the detail returns `purged_at`; a purged first question gives no `preview`.
- **Tombstones:** answers store each retrieval's `document_name`; deleting a Document (`documents/service.py`) clears its retrievals' `chunk_id` and `document_id` in the same transaction. The Trace (`TracedChunkOut`) returns `document_deleted` and, for a deleted Document, the kept name; the order and scores of the retrievals are unchanged.
- **Studio:**
  - Organisation settings, General: a **Retention** section (`settings/RetentionWindow.tsx`, `retention.ts`): "Message text and feedback comments are kept for N days, then purged every night. Metrics are kept."; Owners change it (number field, 7 to 3650, "Saved."; an out-of-range value is explained); Editors read it.
  - Conversations viewer (`projects/ConversationsTab.tsx`): Owners get **Delete Conversation** with a confirmation ("Its Messages' text and feedback comments will be purged now and can't be recovered. Its numbers stay in the metrics."); a deleted Conversation says "Deleted on request <time>"; a purged Message says "Text purged <time>: it was older than the Retention Window." or "…: the Conversation was deleted on request."; the list shows "(deleted on request)" or "(text purged)" in place of the first question.
  - Trace drawer (`projects/TraceDrawer.tsx`): a deleted Document's Chunk reads "Chunk from deleted Document <name>" ("Chunk from a deleted Document" when no name was kept).
- **Generated API client** regenerated. **Glossary:** **Retention Window** completed; new **Purge**, **Deleting a Conversation**, **Tombstone**.

## Gaps and judgement calls

- **Seams not confirmed with a human.** The TDD skill asks for seams to be agreed first; no human is reachable, so the spec's own seams were used.
- **Range 7 to 3650 days.** The spec gives only the default (90). The minimum of 7 keeps the purge clear of live Conversations (a Conversation token lasts 24 hours from the last activity), so a resumed widget never shows emptied Messages of an active chat; 3650 (ten years) is an upper bound against typos.
- **Deleting a Conversation purges, it doesn't remove rows.** The spec says manual deletion goes "through the same purge path"; the Conversation and its Messages stay as numbers (so Version KPIs, rollups and cost don't move), marked `deleted_at` and shown as deleted in the viewer. Its Conversation token is cleared so the Visitor's widget stops resuming it. Owners only (the spec's user story is an Owner's).
- **What is purged:** Message `content`, Message Feedback `comment`, and the free-text `reason` of each Guardrail outcome (the LLM classifier writes "what in the message led to the label", which can quote the Visitor; the spec lists only text and comments, so this is a judgement call on the side of privacy). Kept: every number and attribution, Guardrail outcomes' layer, verdict, action and score, Conversation Ratings and their change log (scores only), Message retrievals (IDs, scores, Document names). Chunk text shown in a Trace comes from the Knowledge Base, not the Message, so it stays while the Document exists.
- **Rollups first, per day:** the purge clears a Visitor reply only when the rollup of its day is final for the Organisation (07-04's `usage_rollup_state`). A Visitor question has no rollup of its own; it waits with the replies of its Organisation's first unfinalised day, which is stricter than needed and harmless. Playground Messages are never rolled up, so they don't wait.
- **The purge runs at 00:35 UTC**, after the hourly rollup's 00:05 run that finalises the previous day; if the rollup fell behind, the purge simply waits a day (shown by the test above).
- **Widget citations:** resuming a Conversation in the widget still shows a deleted Document's citation without a name (unchanged from before); the tombstone is for the Studio's Trace, as the ticket says.
- **Legacy retrievals:** retrievals of Documents deleted before this migration had no name recorded; they are shown as "Chunk from a deleted Document".
- **Migration numbering:** `0038_retention_tombstones` follows candidate's `0037_usage_daily`. Sibling tickets running at the same time may add a `0038`; whoever merges second re-chains `down_revision`.
