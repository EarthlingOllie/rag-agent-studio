## What was built

- **Feedback module** (`backend/app/feedback/`), Conversation Rating alongside Message Feedback:
  - `models.py`, migration `0034_conversation_ratings` (after 08-05's `0033_flagged_chunk_mode`, which follows 07-02's `0032_message_feedback`):
    - `conversation_ratings`: one row per Conversation (unique `conversation_id`, cascades with it): `score` (1–5, nullable, CHECK 1–5), `agent_version_id`, `rated_at`, `prompt_dismissed_at`. The row exists once the Visitor rated or dismissed the prompt.
    - `conversation_rating_changes`: the append-only change log: `score`, `previous_score` (null for the first rating), `agent_version_id`, `changed_at` (the app's Clock), `seq` (orders it).
  - `service.py`: `rate` (finds the Conversation's **last Agent reply by `seq`**, copies its Agent Version into the rating and a change-log row; refuses with `NothingToRateError` before any reply; giving the same score again changes and logs nothing), `dismiss_prompt` (upsert of `prompt_dismissed_at`), `rating_state`, `rating_of`, `rating_changes`.
  - `api.py`: widget routes authenticated by the Conversation token (same 401 rules as the other widget routes, through `embed.service.visitor_conversation`):
    - `PUT /api/widget/agents/{public_id}/conversation/rating` (`rateConversation`), body `{score: 1..5}` (strict integer) → `{score, prompt_dismissed}`; 409 "There is nothing to rate yet." before the Agent has replied; 422 for a bad score.
    - `POST …/conversation/rating/dismissal` (`dismissRatingPrompt`) → 204.
- **Widget resume** (`GET …/conversation`) now also returns `rating: {score, prompt_dismissed}`, and the shell's boot data carries the Live Version's `rating_prompt_after` (the Experience setting from spec 04, default 3, 0 = only at the end).
- **Conversations viewer API**: the list takes `rating=1..5|any|none` and each row has `rating` (current score or null); the detail has `rating: {score, agent_version_number, rated_at, prompt_dismissed_at, changes: [{score, previous_score, agent_version_number, changed_at}]}` or null.
- **Widget** (`frontend/apps/widget/src/Rating.tsx`, new; `Widget.tsx`, `chat.ts`, `styles.ts`): a Rating prompt card above the message box once the Nth reply has finished ("How would you rate this chat?", or the Experience's `ui_text.rate_conversation`), with five toggle buttons "1 out of 5" … "5 out of 5" (`aria-pressed`) in a labelled group and **Not now** (dismissal saved). Once rated: "You rated this chat N out of 5." with **Change rating** (focus moves to the scores; Cancel). **End chat** in a Conversation with a reply and no rating shows "Before you go: …" with the scores, **End without rating** (saves the dismissal, then ends) and **Keep chatting**; focus moves to the first score; rating ends the chat. Status ("Thanks for rating this chat.") and errors are announced.
- **Studio** (`ConversationsTab.tsx`, `conversations.ts`): a **Rating** column ("4 of 5" / "Not rated"), a **Rating** filter (Rated or not / 5 of 5 … 1 of 5 / Rated / Not rated) kept in the URL (`?rating=4`, a score kept as a number so the router doesn't quote it), and on a Visitor Conversation's page a "Conversation Rating" region: "Rated 4 of 5 · for Agent Version v2 · <time>", the dismissal and the "Rating changes" list ("Rated 2 · for … ", "Changed from 2 to 4 · for …").
- **Generated API client** regenerated. **Glossary**: **Conversation Rating** expanded; **Rating prompt** and **Rating change log** added; **Conversations viewer** updated.

## Gaps and judgement calls

- **Seams not confirmed with a human.** The TDD skill asks for the seams to be agreed first; no human is reachable, so the spec's own seams were used.
- **"On end" is asked before the chat ends**, not after: ending forgets the Conversation token (spec 06), so the widget asks first ("Before you go") and ends once the Visitor rates or chooses End without rating (which saves a dismissal first). **Keep chatting** cancels. Only when the Conversation has an Agent reply (there is nothing to rate before) and no rating; a dismissal earlier doesn't stop it (user story 6). **New chat** doesn't ask.
- **The server refuses a rating before any reply** (409): a rating must be attributable to a Version.
- **Giving the same score again** is not a change: nothing is logged and the attribution stays. The change log includes the first rating (previous score null), so it is the full history.
- **No "remove rating"**: the spec allows change, not removal.
- **Rating doesn't count as Conversation activity**, like Message Feedback: it doesn't slide the token's 24-hour window.
- **Rating a retired Agent's Conversation** is still accepted while its token is valid (same rule as feedback and ending).
- **The rating filter's `none`** includes Playground Conversations (they can't be rated); combine with Show = Visitors only.
- **Rollups and the mean rating KPI** are ticket 07-04; this ticket stores what it will read (`conversation_ratings.score` and `agent_version_id`, indexed; the change log).
- **Migration numbering:** `0034_conversation_ratings` follows candidate's `0033_flagged_chunk_mode` (08-05, merged while this ticket was in progress; renumbered in `25b73a8`). A ticket merging first with another `0034` means re-chaining `down_revision` at merge time.
- **Small edits outside the module:** `embed/service.py` (resume returns the rating), `embed/api.py` (`WidgetConversationOut.rating`, boot `rating_prompt_after`), `conversations/*` (filter, column, detail).
