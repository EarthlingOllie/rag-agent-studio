# 03: `make rehearse` reaches a passing smoke check

**Ticket:** `23-03` · **Spec:** [Rehearsing the AWS deployment on Floci](../../specs/23-floci-rehearsal-spec.md)

**What to build:** One command starts Floci, applies the same modules through a `local` environment, pushes the images, runs the migration, rolls the services, uploads the Studio and passes the existing smoke check, with no AWS account.

**Blocked by:**
- `23-02`

**Status:** done

- [x] A `local` environment root composes the same modules as the demo and differs only in inputs and provider settings; its state is in a bucket in Floci with a lock file
- [x] A rehearsal Compose file, separate from `make dev`, runs the pinned Floci with its settings in one place, each with a comment saying which emulator gap it covers; it uses port 4566 and stops `make dev`'s Floci first (23-01: a changed `FLOCI_PORT` breaks the health check and queue URLs), and pre-pulls the pgvector, Valkey and `registry:2` images, failing clearly on a Docker Hub rate limit
- [x] The emulated database has pgvector, the cache keeps TLS and its auth token, and CloudFront's origin-facing prefix list is supplied to the emulator
- [x] The tasks trust the emulator's CA (23-01: Floci 2.5.0 gives ECS tasks no CA bundle): the pushed image carries it and `SSL_CERT_FILE` points at it, so the cache's TLS and the HTTPS queue URLs verify
- [x] The deploy script takes the registry address from Terraform's outputs and the expected image architecture from an argument, defaulting to today's behaviour, and logs in to the repository address's host (the emulator's `proxyEndpoint` names another host)
- [x] A wrapper exports the emulator endpoint and test credentials, makes `000000000000.<endpoint host>` resolve to the emulator (23-01: the provider reads bucket tags through S3 Control with that host, and the apply hangs otherwise), creates the state bucket with the region's location constraint, selects `local` and calls the unchanged deploy script
- [x] `make rehearse` ends with the smoke check passing against the emulated CloudFront address, on Intel and Apple-silicon machines
- [x] `make rehearse-down` destroys the environment and removes Floci's containers and data; a second `make rehearse` then succeeds
- [x] A clear message is shown when Docker socket access or memory is insufficient
- [x] `local` sets `managed_nat`, the `X86_64` architecture on Intel hosts, the origin `localhost`, the database port 7001, and sizes from 23-01: each worker pool one job per task at 1 vCPU / 3 GB, the API 3 GB
- [x] The deploy scripts' tests cover the registry, the architecture argument and the wrapper; the `local` environment passes `make infra-check` and the backend test accepts its state key
- [x] Tests cover the new behaviour at the highest seam (see [shared test seams](../../specs/README.md#shared-test-seams)); 100% line and branch coverage holds
- [x] New domain terms are added to `GLOSSARY.md`; ADRs updated if a decision changed

## How it was run

On 2026-11-27 in the x86_64 sandbox (4 vCPU, 15.7 GB, Docker 29.9.3), Floci 2.5.0. Terraform 1.14.0 and the AWS CLI 2.31.0 ran in containers on the rehearsal's internal `studio-rehearsal-tools` network, from which AWS hosts do not resolve and only Floci answers (checked first: `wget https://sts.amazonaws.com` there gives `bad address`), with the dummy credentials `test`/`test`. The sandbox could not reach Docker Hub without a rate limit, the Terraform registry or ModelScope, so the run used `REHEARSAL_IMAGE_MIRROR=mirror.gcr.io`, a provider mirror passed through `REHEARSAL_TOOLS_DOCKER_ARGS`, and images built beforehand (`REHEARSAL_BUILD=false`) with the backend's documented `BUNDLE_OCR_MODELS=false` (RapidOCR's models come from ModelScope); the build itself ran on a sandbox-only base image that trusts the sandbox's proxy, removed afterwards. Logs are in [23-03-evidence](23-03-evidence/).

## Evidence

**`local` environment, state in Floci.** `infra/envs/local` composes the demo's modules; `infra/tests/compose.test.sh` now fails if any environment composes another set (checked by removing one module from a copy: `FAIL envs/local: composes ... but envs/demo composes ...`). It differs in inputs (each commented with the 23-01 gap it covers) and provider settings (path-style S3, no credential or metadata checks; endpoint and keys from the environment). `backend.tf` is S3 with `use_lockfile = true`, key `envs/local/terraform.tfstate`, plus path style and the three skip settings; the wrapper creates the bucket `studio-local-tfstate` in Floci. Both runs configured the backend and the bucket holds `envs/local/terraform.tfstate` afterwards ([teardown-and-second-run.log](23-03-evidence/teardown-and-second-run.log)). `infra/envs/local/tests/local.tftest.hcl` (8 runs) checks the names, the registry, the inputs, the sizes, the architecture and the deploy output against a provider mocked with Floci's values.

**Rehearsal Compose file.** `infra/rehearsal/compose.yml` pins `floci/floci:2.5.0` (the version `make dev` uses), holds every Floci setting with a comment naming the gap, publishes 4566, mounts the Docker socket and `prefix-lists.json`, and fixes the rehearsal network's subnet (172.29.0.0/16) because the catalogue names it. The wrapper stops whatever Compose `floci` service other than its own holds port 4566 (`up_stops_make_devs_floci_then_starts_the_rehearsals_and_reads_its_ca`, `up_leaves_the_rehearsals_own_floci_running`), and pulls `floci/floci`, `pgvector/pgvector:0.8.1-pg16`, `valkey/valkey:7.2`, `registry:2` and the two tool images first; a Docker Hub rate limit stops it with a message naming `docker login` and `REHEARSAL_IMAGE_MIRROR` (`up_fails_clearly_on_a_docker_hub_rate_limit`), and a mirror's images are tagged with the names Floci asks for (`up_pulls_through_a_docker_hub_mirror_and_tags_the_names_floci_asks_for`).

**pgvector, cache TLS and token, prefix list.** The migration task ran `alembic upgrade head` (which creates the `vector` extension) and exited 0 in both runs; `/api/health` through the distribution answers `{"status":"ok","checks":{"database":"ok","redis":"ok"}}` ([rehearse-first-run.log](23-03-evidence/rehearse-first-run.log)). The tasks have `REDIS_TLS=true` and `REDIS_AUTH_TOKEN` from Secrets Manager, and the API's `TRUSTED_PROXIES` is `10.0.0.0/16,127.0.0.0/8,172.29.0.0/16`: the VPC plus the catalogue's list ([task-settings.log](23-03-evidence/task-settings.log)).

**The tasks trust Floci's CA.** The wrapper copies `tls/floci-root-ca.crt` out of Floci and builds `infra/rehearsal/ca.Dockerfile` on the backend image (`update-ca-certificates` adds it to `/etc/ssl/certs/ca-certificates.crt`); `local` points `SSL_CERT_FILE`, `AWS_CA_BUNDLE` and `REQUESTS_CA_BUNDLE` at that bundle. In the worker task a verified TLS connection to the cache names the issuer `Floci Local CA`, and the worker connected to the `https://floci:4566/...` general queue and ran `jobs.sweep` from it ([task-settings.log](23-03-evidence/task-settings.log)). The second run rebuilt the layer on the same tag with Floci's new CA, and it worked again.

**Database TLS (23-02's open question).** Floci's emulated database is a plain pgvector container with `ssl` off (23-01's data-plane.log), so asyncpg's `ssl=require` would refuse it. `infra/modules/ecs`'s `database` input gained `tls` (optional, default `true`, so the demo is unchanged; `infra/modules/ecs/tests/contract.tftest.hcl` `database_tls_is_on_by_default` and `database_tls_can_be_turned_off`, and the demo test asserts `DATABASE_TLS=true` everywhere); `local` sets `false`.

**Deploy script.** `deploy.sh` reads `terraform output -json ecr_repository_urls` after creating the repositories, tags and pushes to those URLs, and logs in to the URL's host (`localhost:4566` on Floci); the account-ID lookup is gone. A third argument names the architecture the image must have (`arm64` by default, or `amd64`). Tests: `pushes_to_the_registry_terraform_outputs`, `pushes_images_of_the_architecture_given`, `refuses_images_not_of_the_architecture_given`, `rejects_the_architecture_'x86_64'|'ARM64'|''`; the existing cases (the demo's ECR, arm64 refused for amd64 images) still pass. In the run: `Login Succeeded` and both pushes to `localhost:4566/000000000000/eu-west-2/rag-agent-studio/*`.

**The wrapper.** `scripts/deploy/rehearse.sh up` exports `AWS_ENDPOINT_URL=http://floci:4566` and the dummy keys and region (and unsets any session token), puts `scripts/deploy/rehearsal` first on PATH so `terraform` and `aws` run on the tools network, where Floci's alias `000000000000.floci` makes the provider's S3 Control host resolve; creates the state bucket with `LocationConstraint=eu-west-2` unless it exists; installs the providers from the default network; and calls the unchanged deploy script with `DEPLOY_ROOT=infra/envs/local`. Terraform keeps the rehearsal's data in `infra/envs/local/.terraform-rehearsal` (`TF_DATA_DIR`), and `local` pins every service the modules use, and its state backend, to `http://floci:4566`, so neither a stray `terraform` run on the machine nor `make infra-check` can reach AWS from this environment (`infra/tests/backend.test.sh` requires the pinned backend). `scripts/deploy/tests/rehearse.test.sh` (31 cases) checks each of these, the order, and that `run-tool.sh` passes only the endpoint, keys, region and `TF_VAR_*` (never `AWS_SESSION_TOKEN` or other secrets).

**`make rehearse` ends with the smoke check passing.** First run: 161 resources applied, migration, four services stable, Studio uploaded, `Smoke check passed: http://e80vttly16c690.cloudfront.localhost:4566` ([rehearse-first-run.log](23-03-evidence/rehearse-first-run.log)). Intel only: the Apple-silicon half needs a Mac (gap below).

**`make rehearse-down`, then a second `make rehearse`.** The destroy step (`destroy.sh` on `local` through the wrapper's settings) destroyed all 166 resources; Floci left its registry container and the registry and database volumes, which `down` removes by Floci's `floci=true` label and the `floci-aws-` prefix. A second `make rehearse` from nothing then failed once on a real bug (its providers step read state through the first run's backend note) and, after the fix (`up_forgets_the_backend_a_previous_rehearsal_configured_before_installing_the_providers`), passed its smoke check ([teardown-and-second-run.log](23-03-evidence/teardown-and-second-run.log)). The `down` command's steps are covered by `down_destroys_the_local_environment_then_removes_floci_and_its_data`, `down_without_a_running_floci_only_removes_what_is_left` and `down_still_removes_floci_when_the_destroy_fails`; see the gaps for how much of it ran here.

**Clear messages.** No Docker socket: "Docker does not answer. Start Docker, and make sure this user may use its socket ..." before anything else runs; less than `REHEARSAL_MIN_MEMORY_GB` (default 8): "Docker has 6 GB of memory, and the rehearsal needs at least 8 GB ..."; an unknown machine architecture is refused (`up_says_so_when_docker_does_not_answer_on_its_socket`, `up_says_so_when_docker_has_too_little_memory`, `up_refuses_an_unknown_machine_architecture`).

**`local`'s settings.** `managed_nat`, `cpu_architecture` `X86_64` by default and `ARM64` when the wrapper runs on an arm64 machine (`up_rehearses_arm64_tasks_on_an_arm64_machine`), `api_origin_domain = "localhost"`, database port 7001, the API, worker-general and worker-runs at 3 GB (512 / 1024 / 1024 CPU) with one job per worker task, read back through the new ecs output `service_tasks` (`fits_a_16_gb_laptop`). Beat got 1 GB: it used 451 of 512 MiB in the first run and 485 MiB in the second ([rehearse-first-run.log](23-03-evidence/rehearse-first-run.log)).

**Tests and `make infra-check`.** The deploy tests cover the registry and the architecture argument, and `rehearse.test.sh` the wrapper and the tool shims; `make infra-check` runs it and covers `infra/envs/local` (fmt, validate, `terraform test`, tflint, Checkov 280 passed / 0 failed); `infra/tests/backend.test.sh` accepts its state key (`ok   local: S3 backend with native locking`) ([infra-check.log](23-03-evidence/infra-check.log), exit 0).

**Coverage.** No backend or frontend code changed, so the 100% gate is unaffected; the new behaviour is shell and Terraform, tested at their seams (the scripts with stubbed tools, the modules and environment with `terraform test`), and the rehearsal itself is the integration test.

**Glossary and ADRs.** No new domain term ("rehearsal" and "emulator" stay out of the glossary, as 23-01 decided). No ADR changes: turning database TLS off is an emulator workaround through an input, not a change to ADR-0021 or the AWS design.

## Gaps and best guesses

- **One call reached AWS by mistake, and is now impossible.** Before the backend and provider endpoints were pinned, `make infra-check` ran `terraform init -backend=false` on the host in `infra/envs/local` while the first rehearsal's backend note was in `.terraform`; Terraform tried to list the state bucket at AWS S3, which refused it (`InvalidAccessKeyId`: the sandbox holds no AWS credential). Nothing was read or written. The fix is above: the rehearsal's own data folder and the endpoints pinned to Floci, checked by `backend.test.sh` and `up_forgets_the_backend_...`; the rehearsal was run again afterwards and passed.
- **A fifth drift, for 23-04:** Floci drops the tags that the provider sends in `CreateFunction`, so the plan after a fresh apply shows the SPA fallback function's tags changing (one later apply stores them through `TagResource`).

- **Apple silicon is not proven.** The ARM64 path (`uname -m` arm64 → `linux/arm64` images, `ARM64` tasks, `deploy.sh ... arm64`) is unit-tested only; a run on a Mac is human-eyes.
- **`make rehearse-down` was not run end to end here.** This session's rules forbid the agent `docker compose down`, so its destroy step ran through the same settings and the rest (removing Floci, its containers, volumes and networks) was done with the equivalent `docker rm -f`, `docker volume rm` and `docker network rm`; the command's own sequence is unit-tested. A human should run `make rehearse-down` once and see `docker ps -a --filter label=floci=true` and `docker volume ls --filter name=floci` come back empty.
- **The rehearsal's image was built with `BUNDLE_OCR_MODELS=false`** (ModelScope is blocked here); `make rehearse` itself builds with the defaults through `make images`.
- **Beat's AWS size (512 MiB)** is near what Beat used here (451-485 MiB under Floci's hard limit): recorded for ticket 22-09 to check on AWS, not changed for the demo.
- **The worker's idle memory** was 2.53 of 3 GB right after start (parent 0.6 GB, one process 1.66 GB with the models loaded); ingestion headroom is 23-04's to prove.
- Floci's workers log `Exception closing connection` from SQLAlchemy's asyncpg pool after `jobs.sweep` succeeds; the job result is unaffected. Not investigated (it is not specific to the emulator as far as seen).
- `destroy.sh` prints "The demo environment is destroyed." for `local` too, and the wrapper passes it the demo workflow's confirmation phrase: the script is reused unchanged on purpose.
