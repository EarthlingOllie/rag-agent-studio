# 04: Two worker pools

**Ticket:** `22-04` · **Spec:** [Lean, scalable infrastructure](../../specs/22-lean-scalable-infrastructure-spec.md)

**What to build:** On AWS the worker becomes a general pool on Fargate Spot and a runs pool on regular Fargate, each serving its own queue, so a long Evaluation Run no longer holds up ingestion and work that restarts for free runs on the cheapest capacity.

**Blocked by:**
- `22-03`

## Gaps and best guesses

- **Deferred (needs a live deploy, ticket 22-09):** that ECS really places `worker-general` on Spot and `worker-runs` on regular Fargate, that switching `worker_spot` updates the running service in place, that the two-minute stop timeout holds through a real Spot interruption, that each pool can receive from its own queue and is refused the other, that the seed's ingestion reaches the general pool through SQS, and that `deploy.sh` reports each real service stable. Nothing here called AWS, planned against real state or applied.
- **The runs pool at 6 GB, not 4.** Measured on this x86_64 sandbox, not on ARM64 Fargate; ONNX Runtime's arena and the model files are much the same size on both. The alternative, 4 GB with `--concurrency=1`, halves the pool's slots; 22-05's scaling policy counts slots per task, so the concurrency stayed at 2 and the memory went up. The real-AWS run (22-09) can confirm it from Container Insights or the task's memory metric.
- **Desired counts.** Both pools default to one task until autoscaling (22-05 sets the runs pool's zero minimum and ignores the count after creation); `desired_counts` is keyed by the four services.
- **Capacity provider strategy on every service.** The API and Beat name `FARGATE` explicitly rather than relying on the cluster default, so one rule covers all four and `launch_type` is gone. On an existing demo, the first apply after this moves each service from launch type to a capacity provider strategy, which AWS applies as a new deployment.
- **The seed's queue permission** was missing since 22-03 (whose criteria did not cover the seed role); it is added here as "the seed task queues its ingestion", sending to both queues like the API.
- **Docs.** `docs/deploy-demo.md` gains a Worker pools section and notes that its cost table predates the pools; recomputing it, and the README's diagram, are ticket 22-08 (the README's deploy summary line now says "the two worker pools").
