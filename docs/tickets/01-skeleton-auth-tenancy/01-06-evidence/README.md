## Decisions and notes (best guesses recorded instead of asking)

- **Delay means refusing early attempts, not sleeping.** A delayed attempt gets 429 with `Retry-After` straight away. This keeps API workers free, and it works with the controllable clock. The password isn't checked during a delay or lockout, for registered and unknown emails alike.
- **Thresholds.** Accounts get 3 free failures and lock at 10. IPs get 20 free failures and lock at 100, so one shared office or NAT address isn't locked out by a few typos. Delays start at 1 s, double, and are capped at 30 s. The lockout lasts 15 minutes, and a counter is forgotten 15 minutes after its last failure. All of these are settings.
- **Refused attempts don't count**, so a lockout always ends on time. A successful sign-in clears the account counter but not the IP counter, so a valid account can't be used to reset an attacker's IP counter. A known trade-off of any account lockout: someone who knows a Member's email can keep that account locked. The per-account lockout is what the spec asks for.
- **Audit scope.** An Audit Event needs an Organisation (01-05's table has a non-null `organisation_id`). So lockouts are audited only when the email belongs to a Member, once in each of their Organisations. IP lockouts triggered by unknown emails are only logged. Recording happens after the failed answer is decided, and only on the one request that crosses the lockout threshold, so the response body and headers stay identical. The extra database write on that request is a small timing difference. Action name: `member.locked_out` (01-05's Audit tab fixtures already use this name).
- **Client IP.** The IP is the ASGI client address. uvicorn rewrites it from `X-Forwarded-For` only for proxies listed in `FORWARDED_ALLOW_IPS`. Compose now sets `FORWARDED_ALLOW_IPS: "*"`, and the Studio dev proxy sends `xfwd`, so local limits count per browser (the stack demo shows per-IP keys such as `203.0.113.7`). **Follow-up for deployment (09-0x):** set `FORWARDED_ALLOW_IPS` to the load balancer's addresses. Otherwise all visitors share one IP counter.
- **Clock port.** `app/core/clock.py` defines `Clock` and `SystemClock`, and the app keeps the clock on `app.state.clock`. The test fake is `tests/fakes/clock.py` `ControllableClock`, installed by the `clock` fixture. The throttle compares clock times stored in Redis, and Redis expiry only clears old keys. The `app` fixture deletes `sign-in-failures:*` keys before each test, because the shared test Redis would otherwise carry counters between tests.
- **Race.** The check and the count are separate Redis calls, so a burst of parallel requests can squeeze in a few extra attempts before a delay applies. Counting itself is atomic (Lua).
