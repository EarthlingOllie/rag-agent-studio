## Decisions and notes (best guesses recorded instead of asking)

- **Audit Events before 01-05.** 01-11 is blocked only by 01-04, but it has to record Audit Events, and 01-05 (the audit module and its list endpoint) was still being built in parallel. This ticket therefore adds a minimal `app/audit/` module: the `audit_events` table and `record()`, shaped as spec 01 describes (actor, Organisation, action, target, before/after, time). 01-05 still owns:
  - redaction of secret-like fields;
  - append-only enforcement;
  - the Owner-only list endpoint and the Audit tab.

  **Merge note:** whichever of 01-05 and 01-11 merges second must reconcile `app/audit/` and the migration chain. Both add revision `0003` after `0002`, so the second one needs renumbering to `0004` and must reuse the existing `audit_events` table.
- **One event per Organisation.** MFA belongs to the Member, not to one Organisation, so each MFA Audit Event is written once in every Organisation the Member belongs to. Each Organisation's Owners can then see it.
- **MFA tables are platform-level**, like `members`. They are `mfa_factors` (one per Member: sealed secret, `confirmed_at`, `last_used_step`) and `mfa_recovery_codes`. `PLATFORM_TABLES` lists them, so the "every tenant table has `organisation_id`" guard still holds for everything else.
- **One code field everywhere.** `verify`, `disable` and `recovery-codes` take `code`. Six digits are checked as TOTP, anything else as a Recovery Code. This keeps the UI and the API small, and it means a Member who lost their phone can still turn MFA off with a Recovery Code.
- **Status codes.** A wrong code is `400 Code is incorrect`. A missing, expired or exhausted MFA-pending state is `401 Sign in again`. Conflicts (already on, not on, nothing to confirm) are 409. The password step for an MFA Member is `202`, so 01-04's `200` contract is unchanged for everyone else.
- **Replacing Recovery Codes** (`POST /api/auth/mfa/recovery-codes`) wasn't required, but it is the natural "recovery codes screen" action and it is recorded as `mfa.recovery_codes_replaced`.
- **Recovery Codes use SHA-256, not argon2.** They carry 80 random bits, so a slow hash adds nothing. A fast lookup by hash also lets the conditional UPDATE use the code atomically.
- **Clock port.** `app/core/clock.py` (`Clock`, `SystemClock`, `ControllableClock`, `get_clock`) is new. Tests override `get_clock`. 01-06 may add its own clock in parallel; the two should be merged into one port.
- **The Studio page is "Security"** under the Organisation shell, not the spec's "Profile". 01-07 (change password) is building in parallel and may add a Profile page; MFA can move there when both have merged.
- **KEY_WRAPPER only accepts `local` for now.** The AWS KMS adapter is spec 02/09 work (botocore Stubber tests, task role). Nothing else changed.
