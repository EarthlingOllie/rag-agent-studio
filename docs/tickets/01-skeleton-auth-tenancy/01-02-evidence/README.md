## Sandbox notes (local / test-double routes used)

- **No AWS account.** As the spec intends, deploy builds the images, and every push, apply, destroy and `plan` step is skipped. That skip is proven on GitHub's runner, not simulated.
- **Tool downloads.** The sandbox's egress proxy blocks `ghcr.io`, `get.trivy.dev` and Playwright's browser CDN, and Docker Hub rate-limits pulls. Terraform, TFLint, gitleaks and Trivy came from the same pinned, checksum-verified release URLs as CI (`scripts/ci/install-tools.sh`). Checkov came from PyPI. For Playwright, the sandbox's Chrome for Testing was used through `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`, which the config supports. CI uses Playwright's own Chromium.
- **Image builds and the second stack.** As in 01-01, images were built from the committed Dockerfiles. The only addition was the proxy CA and proxy environment, inserted after the first (download) `FROM`. The runtime stages are unchanged. The stack ran under compose project `rag0102`, with a sandbox override that moved host ports and used those pre-built images, because another ticket's stack was using the default ports on the same daemon. Everything else in `docker-compose.yml`, including the new Studio health check, was used unchanged. GitHub's e2e run uses plain `make e2e`.
- **Checkov's guideline lookup** (`api0.prismacloud.io`) is blocked here. `infra/.checkov.yaml` sets `skip-download: true`, so the run is offline and identical in CI.
