- **End-to-end seam.** Playwright runs against the compose stack, with axe.

## Decisions and notes (best guesses recorded instead of asking)

- **The policy check lives in `RequireRole`.** That is the one dependency every Organisation route already declares, so no route can miss the policy. The guard test still sees one policy dependency per route.
- **Order of checks:** not a Member (404), then the MFA policy (403 with its own message), then the role (403 "Only Owners can do this"). The MFA message comes first so that the Studio and the Member learn the one thing that unblocks them.
- **Every route is refused, including `leave`.** The ticket says "refuses that Organisation's routes". A Member who doesn't want MFA can't leave until they enrol, or until an Owner removes them. Allowing `leave` would be a one-line exception if wanted.
- **An Owner needs MFA before requiring it** (409 otherwise). Without this, an Owner could lock themselves and every other Member out at once. Turning the policy off never needs MFA. In practice an Owner without MFA can't reach the route while the policy is on.
- **Turning MFA off is refused first,** before the password and code are checked. A refused attempt therefore never uses up a code or counts as a wrong password. The message names every Organisation that requires MFA, so the Member knows whom to ask.
- **Route shape:** `PUT …/mfa-policy {"require_mfa": bool}` (idempotent), rather than a general `PATCH` on the Organisation, since no other Organisation setting exists yet. It answers with `OrganisationOut`.
- **Studio copy** says "two-factor authentication", as 01-11's screens do. The glossary allows that in Studio copy, but not in code or docs.
- **The Studio redirect is driven by `/api/auth/me`.** It reads `organisations[].mfa_required` and `member.mfa_enabled`. The header (Organisation switcher, Profile link, Sign out) stays, so the Member can switch to an Organisation that doesn't require MFA, or sign out. The Profile page also redirects to Security while enrolment is due.
- **A signed-in Member's open tab** learns about a new policy at its next session refetch (window focus or reload). Until then the API already refuses every request with the MFA message. The e2e test covers the "next visit" by signing in again.
