## Decisions and notes (best guesses recorded instead of asking)

- **Sign-up also signs the Member in.** It returns `201` with the same body as sign-in and sets the cookie, so the flow goes straight to the shell. The 01-02 `signedInPage` fixture still works: it signs up and then signs in, which rotates the session.
- **A taken email at sign-up answers 409 `Email already registered`.** The criterion on identical errors is about sign-in, and 01-02's harness contract expects this 409. Spec 01 doesn't ask sign-up to hide registration. Email verification isn't in scope.
- **Validation.** Names and the Organisation name are trimmed and must have 1 to 200 characters. Emails use a deliberately loose pattern (pydantic's `EmailStr` rejects the reserved `.test` domain the e2e fixtures use) and are normalised to lower case. Passwords need 12 to 256 characters. The cap stops very long inputs from costing argon2 CPU.
- **Cookie name and attributes.** The cookie is `studio_session`. It is always `Secure`; browsers accept that from `http://localhost`, which the e2e run confirms. There is no `__Host-` prefix, so a later custom domain can choose. The TTL is set by `SESSION_TTL_SECONDS` (default 14 days, added to `.env.example`).
- **The Organisation is in the Studio URL** (`/organisations/$organisationId/...`), matching the API's path-scoped routes, ready for the 01-10 switcher.
- **Role policy.** `Scope` only checks membership. Role-based 403s per route (Owner-only) arrive with 01-09, which will extend the same dependency.
- **Backend test fixtures** (`tests/conftest.py`) for later tickets: `client` (HTTPS base URL, so the Secure cookie round-trips), `new_client`, `tenant_factory`, `owner` and `new_member_details`. The test database is migrated once per run.
- **Benign log line.** Running `test_migrations.py` alone can print one `I/O operation on closed file` line from the migrations' console span exporter at interpreter exit, after pytest has closed stdout. The run still exits 0, and the line doesn't appear in the full suite. It is filtered out of `auth-api-tests.log`.

## Sandbox notes (local / test-double routes used)

- **No external services or credentials.** Auth needs only Postgres and Redis, the real ones from compose. Nothing is faked in the backend tests.
- **Image builds and the second stack.** As in 01-02 and 01-03, the images were built from the committed Dockerfiles. The only addition was the sandbox proxy CA and proxy environment, in the first build stage. The stack ran as compose project `rag0104`, with a sandbox override that moves host ports (Studio on `25173`) and uses those images, because another stack was using the default ports. `docker-compose.yml` was otherwise unchanged. GitHub's e2e run uses plain `make e2e`, and it is green.
- **Chromium.** Playwright's browser CDN is blocked here, so the sandbox's preinstalled Chromium was used through `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. CI uses Playwright's own browser.
