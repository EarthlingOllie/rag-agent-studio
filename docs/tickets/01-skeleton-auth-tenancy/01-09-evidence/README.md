# Evidence: ticket 01-09, member management and role enforcement

Branch `ticket/01-09-member-management`, based on `origin/candidate` at `d70118a` (01-08 merged). The code is at commit `2c113e7`. The commit after it only adds this folder and the ticket status.

Most logs come from a fresh `git clone` of the branch from GitHub at `2c113e7`. There are two exceptions:
- `mutation-proof.log` ran in the branch worktree at the same commit.
- The screenshots were taken from the stack built from that clone.

Postgres+pgvector and Redis came from the shared `docker compose` services. These tests used their own database and Redis DB: `TEST_DATABASE_URL=…/studio_test_c0109` and `TEST_REDIS_URL=…/8`, or `studio_test_w0109` and `/9` for the worktree. Each log starts with its commands and ends with its exit code.

**Seams under test.** These come from spec 01's testing decisions and the shared test seams. There was no one to confirm them with, so this is the recorded choice.
- **API seam.** It covers all member behaviour, using the in-process `httpx` client against real Postgres and Redis, with the **controllable clock** for Audit Event times.
  - Outcomes are observed through the API: the Members list, `/api/auth/me` memberships, the answers of Organisation-scoped routes, and Audit Events from the Audit list endpoint. No test reads tables.
  - A new fixture, `member_factory`, adds a signed-in Member with a role through a real Invite. The spec calls this the "signed-in client per role".
- **Policy guard.** `test_each_organisation_scoped_route_declares_its_role_with_one_policy` reads each route's dependency tree from the routers in `app.main.ROUTERS`. It is an architecture check, not a behaviour test. It is the only way to show that "one policy dependency declares the required role per route". The behaviour behind it (Editors get 403) is tested separately at the API seam.
- **Network seam.** It covers the Members list, role changes, removal and leaving, using Testing Library with MSW and handlers typed by the generated client.
- **End-to-end seam.** Playwright runs against the compose stack, with axe.

## Decisions and notes (best guesses recorded instead of asking)

- **The Members list is Owner-only.** The ticket says "Owners see every Member", and the Members tab is already Owner-only navigation from 01-08. Editors get 403 from `GET …/members`. Editors leave from General settings, which every Member sees.
- **Leaving is its own route,** `POST /api/organisations/{organisation_id}/leave` (any Member), not `DELETE …/members/{own id}`, which stays Owner-only.
  - An Owner can also remove themselves through `DELETE` while another Owner remains. It is recorded as `member.removed`.
  - The Studio doesn't offer Remove on your own row; it offers Leave.
- **An Owner may step down** (demote themselves) while another Owner remains.
- **Last-Owner answer is 409 Conflict,** with a message that says what to do. The Studio shows that message as it is.
- **Concurrency.** The Organisation row lock (rather than a database trigger or constraint) keeps the invariant under concurrent requests.
  - The concurrent-demotion test accepts 403 or 409 for the loser. If the winner commits before the loser's request is authorised, the loser is already an Editor, so the policy refuses it first.
  - The concurrent-leave test has no such ambiguity, and it fails without the lock.
- **Policy shape.** `RequireRole` is a frozen dataclass, so FastAPI caches it per request, and tests can find it in a route's dependency tree.
  - `app.main.ROUTERS` lists the routers so the guard test can read each route's dependencies. FastAPI 0.162 wraps included routers in a private type, so the guard doesn't walk `app.routes`.
  - `Scope` and `OwnerScope` keep their 01-08 names, so other in-flight tickets' routes still work.
- **The isolation test's `prepare` steps** now also receive `member_factory`. They can then add Members: the member-route targets, and a second Owner so the caller of `leave` isn't the last Owner. Existing `prepare` steps take the extra argument and ignore it.
- **The 01-08 invite e2e test** now waits for the Members table before inviting. Without the wait, the Members list's "Loading Members…" status could sit beside the invite's status and break the test's `getByRole("status")`. This was found by the first e2e run.
- **The General settings placeholder text** ("Members, roles and security settings will appear here.") is replaced by the Leave section. 01-05's Audit test now checks for the Leave button there instead.
