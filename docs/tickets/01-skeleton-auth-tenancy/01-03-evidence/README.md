## Decisions and notes

- **Console output is JSON.** With no token, spans go to stdout through OpenTelemetry's `ConsoleSpanExporter`, one JSON object per line, instead of Logfire's coloured console. Container stdout is then machine-readable throughout. This is still "the console" in the spec's sense.
- **The project owns the exporters.** `logfire.configure(send_to_logfire=False, console=False, additional_span_processors=[...])` with our own Logfire OTLP exporter or console exporter. This lets every exporter sit behind both Logfire's scrubber and `ScrubbedMessageProcessor`. Logfire's built-in exporter could not be wrapped.
- **SQLAlchemy 2.1.** `opentelemetry-instrumentation-sqlalchemy` 0.66b2 declares support only for `< 2.1`, so `skip_dep_check=True` is passed. The tests and the container run show real query spans. Only one engine per process is traced: an app rebuilt in the same process (as in tests) re-points the instrumentation.
- **`distributed_tracing=True`.** This lets Celery workers join the trace of the request that queued the task.
- **`httpx` is now a runtime dependency.** The production image failed to start without it, because `instrument_httpx` requires it. The container run in this evidence caught that, and it is fixed.
- **One non-JSON line.** On SIGTERM, Celery writes `worker: Warm shutdown (MainProcess)` straight to stdout, outside logging. The worker tests allow exactly that line.
- **gitleaks allowlist.** After merging `candidate` (which added the full-history gitleaks gate from 01-02), gitleaks flagged the fake `PASSWORD` fixture in `tests/integration/test_telemetry.py`. It is a made-up value the scrubbing test proves is never exported. The finding in commit `1bdc0b4` is allowlisted by fingerprint in `.gitleaksignore`, and the line carries `# gitleaks:allow`. `make secret-scan` and `make audit` are clean.
- **Spans flush on API shutdown.** Uvicorn re-raises SIGTERM after a graceful shutdown, so atexit hooks do not run. The lifespan flushes telemetry on shutdown.

## Sandbox notes (local / test-double routes used)

- **No Logfire account is used.** The Logfire path is proven against a local HTTP server that receives the real OTLP/protobuf export. That is the spec-allowed adapter-fake route. A real token only changes the endpoint (`https://logfire-<region>.pydantic.dev/v1/traces`).
- **Docker image builds.** As in 01-01, the sandbox proxy needs its CA inside `docker build`. The backend image was built from the committed `backend/Dockerfile` with two lines added after `FROM` (proxy CA and proxy environment). The api, worker and beat containers were started with `docker run` on the compose network, using the exact `docker-compose.yml` commands, with database `studio_0103` and Redis DB 13. This kept them separate from a stack another ticket build was using.
- The worker runs as root in the sandbox's host-side subprocess tests. Celery's root-user `SecurityWarning` is routed through logging as JSON. In the image the services run as the non-root `studio` user.
