**Seams under test** (spec 01 and the shared test seams):

- The **API seam** covers all audit behaviour. It uses the in-process `httpx` client with the app's lifespan, and real Postgres and Redis. Events are written through the audit module's one public operation, `app.audit.record`, which later specs call next to each change. They are read back only through the Owner-only endpoints.
- The **network seam** covers the Audit tab: Testing Library with MSW, using handlers typed by the generated client.
- The **end-to-end seam** is Playwright against the compose stack, with axe.

Three tests touch the database directly, and only for behaviour with no API surface: the stored row holds no secret, the append-only triggers refuse `UPDATE`/`DELETE`/`TRUNCATE`, and a failed sign-up leaves no event. Nothing in the API can make an Editor until invites arrive (01-08), so the tests insert that membership row directly (`add_member` in `test_audit_events.py`).

## Decisions and notes (best guesses recorded instead of asking)

- **Seams were not confirmed with a person.** The TDD skill asks for that, but this run was autonomous. The seams used are the ones spec 01 and `docs/specs/README.md` already name.
- **`record` takes explicit IDs, not an `OrganisationScope`.** Some security events have no signed-in actor in the Organisation, such as the lockouts in 01-06. Reads still require an Owner's scope. `occurred_at` is optional so that later backfills and tests can set the time. There is no clock port yet; parallel tickets 01-06 and 01-07 introduce time-dependent behaviour.
- **Action names** are dotted, `<thing>.<past-tense verb>`, for example `organisation.created`. Targets are `(type, id)`, and the ID is optional.
- **Date filtering.** The API takes `start` inclusive and `end` exclusive, as aware ISO times. The Studio's From and To fields are whole UTC days, both inclusive (To becomes the next day's 00:00Z). Times are shown in UTC, so every Owner sees the same values.
- **Pagination** is page/page size with a total (offset based). Audit volumes per Organisation are small, and page numbers suit the tab.
- **Facets endpoint.** No members-list API exists yet (01-09), so the actor and action menus need their own Owner-only source. That source is `…/audit-events/facets`.
- **Append-only at the database.** The triggers refuse `UPDATE`, `DELETE` and `TRUNCATE`. The foreign keys to `organisations` and `members` have no `ON DELETE` action. Organisation deletion is out of scope (spec 01), so this blocks nothing today. A later retention or deletion ticket must decide what happens to Audit Events.
- **Migration revision ID** is `0003_audit` rather than `0003`, so it can't collide with a parallel ticket's `0003`. Whichever merges second rebases its `down_revision`.
- **gitleaks.** The redaction test holds two made-up API keys. They are allowlisted by fingerprint in `.gitleaksignore`, as in 01-03.

## Sandbox notes (local / test-double routes used)

- **No external services or credentials.** Audit needs only Postgres and Redis, the real ones from compose. Nothing is faked in the backend tests.
- **Images and the stack.** The images were built from the committed Dockerfiles. The only addition was the sandbox proxy CA and proxy environment, in the first build stage (`sb0105/build.sh`, same as 01-04). The stack ran as compose project `rag0105` with a sandbox override that moves host ports (Studio on `35173`), so it could run beside other tickets' stacks. `docker-compose.yml` is unchanged.
- **Chromium.** Playwright's browser CDN is blocked here, so the sandbox's preinstalled Chromium was used through `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.
- **One unrelated flake.** The first fresh-clone backend run used Redis DB 11 and had one failure, in the existing `test_logging.py::test_beat_writes_only_json_lines`: a raw traceback line from the Beat subprocess at shutdown. It passed in six isolated reruns and in the full rerun on Redis DB 7 (the committed log). This ticket doesn't touch Beat or logging. Parallel ticket builds were using the same Redis server at the time.
- **Not run here:** GitHub Actions. This step pushes the branch without opening a PR, and the workflows run on PRs. The `pip-audit`, `pnpm audit` and Trivy gates also weren't run, because no dependency or Dockerfile changed. The PR stage runs CI.
