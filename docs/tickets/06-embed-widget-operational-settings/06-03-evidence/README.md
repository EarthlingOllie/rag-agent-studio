## What was built

- **Theme resolution on the server** (`backend/app/theme/resolve.py`): `with_colours` (the Organisation's Theme with an Agent's colour tokens replacing the Theme's), `theme_stylesheet` (exactly what `themeStylesheet` in `@studio/ui` writes, light, dark, or both with a `prefers-color-scheme: dark` block for auto), `font_stylesheet_url`, `widget_theme`.
- **Theme override** (`backend/app/embed/branding.py`, `branding_api.py`, migration `20261107_0030_agent_theme_override.py`): `agents.theme_colours` (JSONB, `{}` by default) and `agents.avatar` (JSONB, the stored image as the Theme's are). Routes under `…/agents/{agent_id}/theme-override`: `GET` (any Member), `PUT {colours}` (Owners; any of the six Colour Tokens, each `{light, dark}` hex; unknown tokens or fields are 422), avatar `POST …/avatar/uploads`, `PUT …/avatar`, `DELETE …/avatar` (Owners; presign, PUT, confirm, as the Theme's images, sharing `start_image_upload`/`claim_upload` factored out of `app/theme/images.py`) and `GET …/avatar` (any Member). Every change records `agent.theme_override_updated` with only what changed. It is not part of AgentConfig, so it is not versioned and applies to the next shell.
- **Widget shell** (`backend/app/embed/api.py`, `service.py`): adds `<link>` to the font's Google Fonts stylesheet, `<style id="widget-theme">` with the resolved Theme on `#root`, and in `#widget-boot`: `theme` (mode, launcher type and position, font), `logo_url`, `avatar_url` (the Agent's own, else the Live Version's `avatar_url`, else the Theme's default avatar), and from the **Live Version**: `name` (display name, else the Agent's name), `greeting`, `starter_questions`, `ui_text`, `citations`. `GET /widget/a/{public_id}/avatar` and `/logo` serve the images to Visitors (no session; `public, immutable`, the URL carries the content hash).
- **Citations:** the widget's `citation` SSE event carries the cited `passage`; none is sent when the Live Version's `retrieval.citations` is off.
- **Loader** (`frontend/apps/widget/src/embed.ts`, 1367 B, 778 B gzipped, within the 2048/1024 budget): reads `data-agent`, `data-launcher` (`bubble`/`inline`; anything else is ignored so the Theme's Launcher applies) and `data-target` (inline container; a selector that matches nothing or is invalid falls back to after the snippet with a console hint). The frame's address carries `?host=<host origin>` and `&launcher=`. It sizes the frame: inline 100% × 560 px in place; bubble fixed in the corner, 88 × 88 closed, `min(420px,100vw)` × `min(680px,100vh)` open, the whole screen when open on a phone (`max-width: 640px`). Layout messages are accepted only when `event.source` is the frame's window, `event.origin` is the frame's origin and the type is `rag-agent-studio:layout`.
- **Widget** (`Widget.tsx`, `chat.ts`, `styles.ts`, `main.tsx`): built from the shared `@studio/ui` primitives (`ChatWindow`, `MessageBubble`, `Composer`, `Launcher`), which read the Theme's CSS variables. Bubble mode opens from the Launcher (focus moves to the message box; Escape or Close returns it to the Launcher); inline is always open. It posts its layout only to the `host` origin (validated: an `http(s)` origin and nothing more; never `*`), and only when framed. Greeting first in the log, starter questions as buttons until the first message, the `send_button` and `unavailable_message` UI text overrides, the Theme's logo and the avatar in the header, and sources as `<details>` that expand to the passage. The page is transparent (the colour scheme is set on `#root`, not the root element) so a closed bubble shows only its Launcher. `prefers-reduced-motion` turns animation off. On phones the open panel fills the frame and the Launcher hides.
- **Shared primitives** (`frontend/packages/ui/src/primitives.tsx`): `ChatWindow` gains `actions`, `logLabel` (a `log`), `className` and a scrolling message list; `MessageBubble` an optional `label`; `Composer` `sendLabel` and `disabled`, and it clears the box by value.
- **Studio:** the Embed section's snippet chooses the Launcher (the Theme's, bubble, or inline with a container selector, HTML-escaped into `data-target`); a new **Widget branding** section (`AgentBranding.tsx`, `branding.ts`) where Owners tick colour tokens to override (starting from the Theme's values), save them, and upload, replace or remove the Agent's avatar; Editors see it read-only.
- **Demo host page** takes `&launcher=inline` (widget in its `#chat` container) or `&launcher=bubble`.
- Generated API client regenerated; `docs/development.md` describes the branded widget.

## Gaps and best guesses

- **Left to other tickets, as the spec splits them:** full WCAG 2.2 AA work (focus trap, live-region announcement once complete, axe on the open widget in light and dark) is 06-07; this ticket moves focus in and back and respects reduced motion. Resume, new and end Conversation are 06-04's, merged in and kept working in the branded widget. The unavailable *event* and Operational Settings' unavailable text (06-02, 06-06); here the Live Version's `ui_text.unavailable_message` replaces the built-in message on a 503 or stream `error`. `rate_conversation` is carried to the widget but rating is spec 07. The Studio's live widget preview on the Embed tab is not built. Auditing the other Operational Settings is 06-02; the override is audited here.
- **Best guesses, recorded instead of asking:**
  - **Avatar precedence:** the Agent's own (override) avatar, then the Live Version's `experience.avatar_url`, then the Theme's default avatar. The override is the Owner's explicit per-Agent brand; the Version's URL is the Editor's versioned choice; the Theme's is the fallback.
  - **The override covers colours and the avatar only** (the spec's "Theme override (colours and avatar)"); font, radius, mode and Launcher stay Organisation-wide. Any subset of the six tokens can be overridden, each with both its light and dark value.
  - **Overrides are stored on the `agents` row** (as 06-01 stored Allowed Origins), not a separate Operational Settings table; 06-02 may move them.
  - **Selector `#root`** for the inlined stylesheet, rather than `:root`, so the iframe's own page has no colour scheme and stays transparent around the closed bubble.
  - **Layout messages flow one way** (widget → host). The widget restricts the target origin to the host origin the loader passed (never `*`), and the loader checks source and origin, which is the validation in both directions; the host sends nothing to the widget, which therefore has nothing to accept.
  - **Resumed sources have no passage:** 06-04's resume endpoint returns each cited source's label and Document name only, so after a reload the sources show as names, not expandable passages; adding the passage there is a small follow-up (`MessageRetrieval.chunk_id` to the Chunk's text) left out to keep this merge to the widget.
  - **Phone breakpoint** 640 px; bubble sizes 88 px closed and 420 × 680 open (clamped to the viewport).
  - The shell links the Google Fonts stylesheet for the Theme's allowlisted font; the shell's CSP is only `frame-ancestors`, so it loads. The sandbox can't reach Google Fonts, so e2e runs on the fallback font.
- **Sandbox limits** (as in earlier tickets): images built with `WITH_PDF=false BUNDLE_MODELS=false` and the egress CA; e2e with `EMBEDDER=fake`; the live suite and Trivy were not run; infra checks not run (no infra change).
