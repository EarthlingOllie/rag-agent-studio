## What was built

- **Data** (migration `backend/migrations/versions/20261107_0030_operational_settings.py`): `agents.unavailable_text` (up to 500 characters, null meaning the platform default). `agents.allowed_origins` (06-01) stays where it was. Both are columns on the Agent itself, not in the Draft's or a Version's AgentConfig snapshot.
- **Service** (`backend/app/embed/service.py`):
  - `operational_settings` / `change_operational_settings`: a partial change (a setting left out is untouched; a blank unavailable text restores the default). The Agent row is locked, the before and after values are compared, and only if something changed an `agent.operational_settings_changed` Audit Event is recorded with the before and after of just the settings that changed. Then commit. Nothing is published and the Draft is not touched.
  - `normalise_origins`: `http`/`https`, host, optional port 1–65535, no path; lower-cased, trailing slash dropped, de-duplicated in order; at most 50. New: a **subdomain wildcard** as the first label over a named site of at least two labels (`https://*.example.com`, `https://*.example.co.uk:8443`; never `*`, `https://*`, `https://*.com`, `https://www.*.example.com`, `http://*.localhost`). **Localhost** (`localhost`, `127.0.0.1`, `[::1]`) may take any port with `:*`; no other host may.
  - `unavailable_text(public_id)`: what the widget API tells Visitors when the Agent can't answer: the 503 with no model to answer with, and the SSE `error` event's `message` on a provider failure (06-01 sent a fixed generic text).
- **API** (`backend/app/embed/api.py`): `GET`/`PATCH …/projects/{project_id}/agents/{agent_id}/operational-settings` (`getOperationalSettings`, `changeOperationalSettings`), Editors and Owners, Organisation-scoped through the one policy dependency. They replace 06-01's `getAllowedOrigins`/`setAllowedOrigins`. A bad origin is a 422 at `["body", "allowed_origins", i]` with "'…' isn't a site address."; nothing is saved and nothing audited.
- **Studio** (`frontend/apps/studio/src/projects/AgentEmbed.tsx`, `embed.ts`): the Embed section edits the Allowed Origins (hint now names wildcards and `http://localhost:*`) and gains an **Unavailable text** box with its own Save ("Saved. Visitors see it from their next message."); empty restores the default. Both are disabled while loading or after a failed load so a save can't overwrite settings it never read.
- **Generated API client** regenerated (`make gen-client`).

## Gaps and best guesses

- **Left to later tickets, as the spec splits it:** rate limits (06-05) and the Token Budget with the SSE `unavailable` event (06-06) will join the Operational Settings and should reuse the Unavailable text; the Studio's live widget preview; resume (06-04); WCAG work on the open widget (06-07).
- **Best guesses, recorded instead of asking:**
  - **Wildcard rule:** only a whole first label (`*.`), over a site of at least two labels, matching CSP's own `*.host` semantics (subdomains only, not the apex). A public-suffix check (rejecting `*.co.uk`) needs a PSL dependency; the two-label rule rejects `*.com` but would accept `*.co.uk`. Recorded, not built.
  - **Localhost any-port** is `:*` (CSP's own port wildcard), only for `localhost`, `127.0.0.1` and `[::1]`.
  - **One PATCH endpoint** for all Operational Settings, replacing 06-01's PUT Allowed Origins, so future settings (rate limits, Token Budget) land in the same audited change. The audit stores only the changed keys.
  - **Unavailable text** is plain text, max 500 characters, blank meaning the default; it replaces the generic message in both the 503 and the SSE `error` event, so Visitors never see provider details.
  - **Proving "can't frame" in e2e:** the browser fetches the shell (200) and then refuses to render it, so the test checks Chrome's console refusal plus the absence of the widget's content in the frame, rather than a network failure.
- **Sandbox limits** (as in earlier tickets): images are built with `WITH_PDF=false BUNDLE_MODELS=false` (`build.sh` adds only the egress proxy CA), and the e2e stack runs `EMBEDDER=fake`, because Hugging Face is blocked here. The live suite and the Trivy scan were not run. Infra checks were not run; this ticket changes no infra.
