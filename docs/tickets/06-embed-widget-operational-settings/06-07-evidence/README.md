## What was built

- **Focus trap and return** (`frontend/apps/widget/src/Widget.tsx`): while the bubble is open, the panel's `onKeyDown` (`trapFocus`) keeps Tab inside it: Tab past the last enabled control wraps to the first, Shift+Tab before the first wraps to the last. Inline (part of the host page) has no trap. Opening, by Enter or Space on the Launcher (a native `button` with `aria-expanded`), moves focus to the message box; closing, by the header's **Close chat** or Escape anywhere in the widget, returns it to the Launcher (06-03 started this; this ticket adds the trap and the tests).
- **Reply announcements** (`frontend/packages/ui/src/primitives.tsx`, `Widget.tsx`): `ChatWindow` takes `announcements`. With it the Conversation `log` is `aria-live="off"` (a streamed reply would otherwise be read token by token) and a visually hidden `role="status"` `aria-live="polite"` region named "Announcements" is rendered. When a reply's stream completes, the widget puts `"<Agent name>: <whole reply>"` there as a new keyed node, so the same words twice are read twice; a failed reply adds nothing (its `role="alert"` error is read instead).
- **A real list in the log**: the `log` is now a wrapper `div` around the `ol` of Messages. axe's `listitem` rule failed on the first run because `role="log"` on the `ol` stripped its list semantics, so the `li`s had no list parent.
- **Reduced motion**: the newest Message scrolls into view (`scrollIntoView({ block: "end" })`), `smooth` normally and `auto` when `matchMedia("(prefers-reduced-motion: reduce)")` matches. The bubble's panel has a 160 ms opening animation (`widget-open`), which the existing `prefers-reduced-motion: reduce` rule in `styles.ts` turns off with every other animation and transition.
- **Labels, focus and targets** (`styles.ts`): every control already had an accessible name (Launcher "Open chat"/"Close chat", header "Close chat", "New chat", "End chat", "Message", the Send button's text, starter questions' text, "Start a new chat"). Added: a 2 px `:focus-visible` ring in the text colour of what the control sits on (`--theme-on-surface` in the body, `--theme-on-primary` in the header and on the Launcher, inset there), so it contrasts as the Theme's text does (WCAG 2.4.7, 1.4.11); header controls at least 28 px tall and sources' `summary` at least 24 px (2.5.8 Target Size).
- **Contrast**: the widget's text pairs are the Theme's Colour Token pairs that `contrastWarnings` already checks (on-primary/primary, on-surface/surface, muted/surface at 4.5:1; accent/surface at 3:1) and the default Theme passes them in light and dark (`contrast.test.ts`, "the default Theme passes WCAG AA in both modes"). axe's `color-contrast` rule (in the WCAG 2 AA tag set) checks every rendered text in the frame in both modes in e2e.
- `frontend/apps/studio/src/test/setup.ts`: jsdom has no `scrollIntoView` or `matchMedia`; both get inert defaults (no preference matches unless a test stubs it).
- `GLOSSARY.md` and `docs/development.md` updated.

## Gaps and best guesses

- **Theme colours an Owner picks** can fail contrast; the Theme editor warns (`contrastWarnings`, 02-05) and never blocks, as the glossary's Contrast warning says. AA is proven for the default Theme and its dark values. The per-Agent colour override (06-03) has no contrast warning of its own in the Studio; adding one is a small follow-up outside this ticket's criteria.
- **No real screen reader** in this sandbox: announcements are proven through the ARIA the browser exposes (a polite status region, a non-live log), not by listening to NVDA/VoiceOver.
- **Best guesses, recorded instead of asking:**
  - The focus trap applies only to the open **bubble** (a modal-like overlay). The inline widget is part of the host page, so trapping Tab there would trap the host page's keyboard users.
  - The announcement reads the Agent's display name and the whole reply text once; sources are not read (they follow in the log for anyone who navigates to them).
  - The panel is not given `role="dialog"`: 06-03's tests and the Studio find it as the region "Chat with …", and the trap plus Escape give dialog behaviour; adding the role would add a second name for the same container.
  - Focus ring colour follows the text colour of the surface it sits on rather than the accent, because the Theme only guarantees text contrast (4.5:1), which also covers the 3:1 non-text requirement.
- **Sandbox limits** (as in earlier tickets): images built with `WITH_PDF=false BUNDLE_MODELS=false` and the egress CA; e2e with `EMBEDDER=fake`; the live suite and Trivy not run; infra checks not run (no infra change).
