## What was built

- **Data** (migration `backend/migrations/versions/20261106_0028_embed.py`):
  - `agents.allowed_origins`: a text array, empty by default (no site may frame the widget).
  - `conversations.token_hash`: the SHA-256 hex of a Visitor Conversation's Conversation token, unique; null for Playground Conversations.
- **Tokens** (`backend/app/embed/tokens.py`): HMAC-SHA256 signing with a key derived (with its own label) from the deployment's key wrapper key, so no new secret is provisioned.
  - Bootstrap token: `wb1.<public_id>.<issued>.<sig>`, bound to the Agent, valid 15 minutes, stateless.
  - Conversation token: `wc1.<conversation_id>.<random nonce>.<sig>`: signed and opaque. Only its hash is stored. It expires 24 hours after the Conversation's last activity, sliding (each message moves `last_activity_at` on).
- **Service** (`backend/app/embed/service.py`): Allowed Origins normalisation and validation (scheme `http`/`https`, host, optional port 1–65535, no path, at most 50, lower-cased, trailing slash dropped, de-duplicated), the `frame-ancestors` policy, the shell data, the bootstrap exchange, and the token check before a question is saved. Serving goes through 05-02's `app.agents.serving` (Live Version config, pinned Instructions, attribution).
- **API** (`backend/app/embed/api.py`):
  - `GET /widget/a/{public_id}` (not in the OpenAPI document): the widget shell. `Content-Security-Policy: frame-ancestors <Allowed Origins>` (`'none'` when empty), `Cache-Control: no-store`, `nosniff`, `no-referrer`. The page holds `#widget-boot` (public ID, name, bootstrap token; JSON with `<`, `>` and `&` escaped) and `<script type="module" src="/widget/assets/widget.js">`. An archived, unknown or not-live Agent (or one in an archived Project) gets the 404 "This assistant is no longer available." shell with no token or script, framable anywhere.
  - `POST /api/widget/agents/{public_id}/conversations` (`startWidgetConversation`): bootstrap token → 201 `{conversation_token}`; 401 tampered, expired or another Agent's; 404 no longer available.
  - `POST /api/widget/agents/{public_id}/messages` (`sendWidgetMessage`), `Authorization: Bearer <conversation token>`: Server-Sent Events `token`, `citation` (`label`, `document_name`), `replace`, `error`, `done` (`message_id`). 401 missing, tampered, forged, expired or another Agent's token; 404 no longer available; 503 "temporarily unavailable" when there is no model to answer with; 422 empty or over-long question. No Studio session is used.
  - `GET`/`PUT …/agents/{agent_id}/allowed-origins` (`getAllowedOrigins`, `setAllowedOrigins`), Editors and Owners, scoped by Organisation through the one policy dependency. A bad entry is a 422 located at `["body", "origins", i]`.
- **Studio** (`frontend/apps/studio/src/projects/AgentEmbed.tsx`, `embed.ts`): the Agent page gains an **Embed** section (not on archived Agents). Before the first publish it says "Publish the Agent to get its Embed Snippet."; after, it shows `<script src="<origin>/embed.js" data-agent="<public ID>" async></script>` and a **Copy snippet** button ("Copied." or "Couldn't copy. Select the snippet and copy it."). An **Allowed Origins** text box (one per line) saves the list and shows the API's reason for a bad entry.
- **Widget** (`frontend/apps/widget`, new workspace package `@studio/widget`):
  - `src/embed.ts` + `src/loader.ts` → `dist/embed.js`: a classic IIFE with no globals (417 bytes, 315 gzipped). It reads `data-agent` from its own `<script>`, and inserts an iframe (`title="Chat"`) for `/widget/a/<public ID>` on the origin the script came from, right after the snippet.
  - `src/main.tsx`, `src/Widget.tsx`, `src/chat.ts` → `dist/widget/assets/widget.js`: a React app that reads `#widget-boot`, exchanges the bootstrap token on the first question, keeps the Conversation token in memory, and streams each reply (tokens, replacement, sources, errors) into an `aria-live` log.
  - **Size budget:** `scripts/check-size.mjs` fails if `embed.js` is over 2048 bytes or 1024 gzipped. `pnpm check-embed-size` builds and checks; it runs in `frontend.yml` after the build and at the end of `make test-frontend`.
- **Compose:** `widget` (a `vite preview` of the widget build, port 5174 inside the network) and `host` (the demo host page, `frontend/apps/widget/host/serve.mjs`, on its own origin, port 5175). The Studio's dev server proxies `/widget/a/` to the API and `/embed.js` and `/widget/assets/` to `widget`, so the iframe shares the API's origin as ADR-0011 has it behind CloudFront. The frontend image builds the widget.
- **Generated API client** regenerated (`make gen-client`). `docs/development.md` describes the embed setup and the host page.

## Test seams

These follow the [shared test seams](../../../specs/README.md#shared-test-seams) and the spec's Testing Decisions. They were not confirmed with a human; they are the ones the spec names.

- **API seam:** `backend/tests/integration/test_embed.py` (23 tests, 34 cases) drives the app in process as a host page's browser would, with a visitor client that has no Studio session, against real Postgres and Redis, using the echoing `FunctionModel` and a controllable clock. Assertions are on HTTP responses, headers and the SSE stream. Two deliberate exceptions read the database, because the behaviour has no API surface for Visitors: the stored token hash (one `SELECT` that also checks the plaintext token appears nowhere in the row) and each answer's attribution columns (as 05-02 did).

- **End-to-end seam:** `frontend/e2e/tests/embed.spec.ts`, Playwright against the compose stack, with axe.

## Gaps and best guesses

- **Left to later tickets, as the spec splits it:**
  - Allowed Origins **wildcards**, an explicit localhost rule, the unavailable text, **auditing** of changes and the "disallowed origin can't frame" e2e (06-02). Here the list is simple: exact `http(s)://host[:port]` entries, validated so nothing can break the CSP header.
  - Theme, per-Agent overrides, **bubble/inline launchers, `data-launcher`/`data-target`, `postMessage` resizing**, greeting, starter questions and UI text, mobile full-screen layout (06-03). The loader injects a plain inline iframe, and the shell inlines only the Agent's name.
  - **Resume:** keeping the Conversation token in iframe storage, getting a Conversation back, new and end Conversation, and the friendly retired message in the widget (06-04). The token's 24-hour sliding expiry is already enforced and tested here. The widget keeps its token in memory, so a reload starts a new Conversation.
  - Rate limits and admission control (06-05), Token Budget and the `unavailable` SSE event (06-06), WCAG 2.2 AA work and axe on the open widget (06-07). With no model to answer, the widget API returns 503 "temporarily unavailable" for now.
  - The Studio's live widget preview on the Embed tab (spec 06 Studio UI), and the S3/CloudFront upload of `embed.js` and `widget/assets` (09-06).
- **Best guesses, recorded instead of asking:**
  - **Signing key.** Tokens are signed with HMAC-SHA256 under a key derived from `LOCAL_KEY_WRAPPER_KEY` with a fixed label. That setting is required in every environment, so no new secret had to be provisioned. A dedicated `WIDGET_TOKEN_SECRET` (rotatable on its own) would be cleaner; adding one means a compose, test and Terraform change.
  - **Bootstrap token** lifetime is 15 minutes, and it is stateless, so it can be exchanged more than once within that time; each exchange starts a new Conversation. Per-IP rate limits (06-05) bound abuse.
  - **The widget API is addressed by the Agent's public ID** (`/api/widget/agents/{public_id}/…`), so a token for one Agent is refused at another's.
  - **Unavailable shell** (archived, unknown or not-live Agent) is a 404 with `frame-ancestors *`: it carries nothing about the Agent, so any page may show it, and Visitors see the message instead of a blocked frame.
  - **Fixed bundle name** `widget/assets/widget.js` (no content hash), because the API's shell names it. Cache-busting belongs with the deploy (09-06).
  - Locally the widget **shares the Studio's origin** (proxied, as CloudFront does with the API in AWS), so the iframe, its bundle and the widget API need no CORS.
- **Sandbox limits** (as in earlier tickets): images are built with `WITH_PDF=false BUNDLE_MODELS=false` (`build.sh` adds only the egress proxy CA), and the e2e stack runs `EMBEDDER=fake`, because Hugging Face is blocked here. The live suite and the Trivy scan were not run. Infra checks were not run; this ticket changes no infra.
